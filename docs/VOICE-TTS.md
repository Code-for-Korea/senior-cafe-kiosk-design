# 음성 안내(TTS) 문장과 설정

기준: 2026-10-28 코드(`src/voice/`). 음성 안내에 필요한 목소리 설정, 읽는 문장 전체, 각 문장을 읽는 때를 모았습니다. 문장을 바꾸면 이 문서도 함께 고쳐 주세요.

## 1. 지금 방식

- **녹음 파일이 있으면 그 파일을 틀고, 없으면** 브라우저에 들어 있는 음성 합성 기능(Web Speech API의 `speechSynthesis`)으로 읽습니다(2026-10-29).
  - 녹음 파일은 `public/voice/` 폴더에 문장 이름표 + 확장자(예: `v_ec8eeca6.mp3`)로 둡니다. 파일을 넣거나 뺀 뒤 `npm run voice:files`를 실행하면 파일 목록(`manifest.json`)이 새로 만들어지고, 없는 파일이 어떤 문장인지 알려 줍니다.
  - 한 줄(파일 하나)씩 차례로 틉니다. 파일이 없는 줄이나 틀지 못한 줄은 그 줄만 브라우저 음성으로 읽어서, 파일이 일부만 있어도 안내가 끊기지 않습니다.
  - 화면에 들어올 때 그 화면의 파일을 미리 받아 둡니다.
  - 파일은 mp3, 96kbps, 모노(소리 통로 1개), 44.1kHz로 둡니다. 받은 파일은 320kbps였는데, 목소리만 담는 파일이라 낮춰서 54개 합계를 8.8MB에서 2.7MB로 줄였습니다. 인터넷이 느려도 파일을 빨리 받기 위해서입니다(2026-11-02). 새로 받은 파일은 `ffmpeg -i <원본> -map_metadata 0 -ac 1 -ar 44100 -c:a libmp3lame -b:a 96k <저장할 파일>`로 바꿔 넣습니다.
- 브라우저 음성으로 읽을 때의 목소리는 기기(운영체제·브라우저)에 깔린 한국어 음성에 따라 달라집니다.
- 화면과 음성은 서로 기다리지 않습니다. 음성이 끝나지 않아도 다음 화면으로 갈 수 있고, 화면이 바뀌면 읽던 안내를 멈춥니다.
- 언어 선택은 선택 표시만 시연하므로, 음성도 한국어만 있습니다.

**TTS가 해 줘야 하는 일 (지금 코드가 쓰는 기능)**
- 문장 여러 개를 차례로 읽기. 안내를 문장 단위로 나눠 넘깁니다.
- 문장마다 시작 알림. 지금 읽는 문장이 가리키는 버튼·칸에 테두리를 그리기 때문입니다.
- 바로 멈추기. 화면이 바뀌거나 손님이 다른 버튼을 누르면 곧바로 멈춥니다.
- 음량 바꾸기. 음량 버튼을 그만 누르고 0.5초 뒤, 읽던 문장부터 새 음량으로 다시 읽습니다. 읽는 안내가 없을 때는 아무 말도 하지 않습니다(바뀐 크기는 ‘다시 듣기’로 들을 수 있습니다).

## 3. 언제 읽나

- 음성 안내는 꺼진 상태로 시작합니다. 손님이 아래 기능바의 ‘음성 안내’를 눌러 켭니다.
- **켤 때**: 소개 문장을 먼저 읽고, 이어서 지금 화면 안내를 모두 읽습니다.
- **화면에 들어올 때**: 한 주문 안에서 같은 화면의 같은 문장은 처음 한 번만 읽습니다. 같은 화면에서 문장이 바뀌면 바뀐 줄만 읽습니다.
- **경고·오류**(아래 표의 ⚠): 나타날 때마다 처음부터 읽습니다.
- **머뭇거릴 때**: 음성이 켜진 채 7초 동안 아무것도 누르지 않으면 지금 화면 안내를 한 번 더 읽습니다(한 화면에 한 번). 기다리기만 하는 화면(⏳)에서는 다시 읽지 않습니다.
- **다시 듣기**: 언제든 지금 화면 안내를 모두 읽습니다.
- **대화상자**: 열려 있으면 대화상자 안내만 읽습니다. 닫고 돌아온 화면은 다시 읽지 않습니다.
- **대기 화면**: 음성 안내가 꺼져 있어도 이 화면에 올 때마다 한 번 안내합니다. 일반 브라우저는 사람이 한 번 누르기 전에는 소리를 막을 수 있어, 실제 기기에서는 소리를 허용하도록 설정해야 합니다.
- **새 주문**(‘처음으로’, 시간 초과, 주문 끝): 음성 안내를 끄고, 음량을 5로 되돌리고, 읽은 기록을 지웁니다.

**읽는 범위 (기획 D-04)**: 다음 행동과 버튼·칸의 위치만 읽습니다. 메뉴 이름·가격·고른 내용·금액은 읽지 않습니다. **바뀌는 숫자는 읽지 않습니다.** 주문번호는 큰 글자와 주문번호표가 맡고, 번호표가 나오지 않은 화면에서만 ‘주문번호는 화면에 크게 적혀 있어요.’라고 자리를 알립니다. 음량을 바꿀 때도 ‘음량 N’을 말하지 않습니다(2026-10-28 사용자 결정). 그래서 모든 문장을 미리 만들어 둘 수 있습니다. 버튼 이름은 화면 글자 그대로 읽습니다.

**문장 규칙 (2026-10-28 사용자 결정)**
- 한 줄에 할 일 하나. 버튼을 알리는 줄은 ‘~하려면, ○○를 눌러 주세요.’처럼 무엇을 하려는지 먼저 말하고, ‘아니면’ 같은 말머리는 쓰지 않습니다. 쉼표는 이번에 고친 줄에만 넣었고, 나머지 줄은 아직 쉼표가 없습니다.
- 같은 상황은 같은 문장으로 읽습니다. 예: 직원을 부른 뒤는 어디서나 ‘직원을 불렀어요. 이 자리에서 잠시 기다려 주세요.’, 고르기 질문은 주문 화면과 장바구니 창이 같은 문장.
- 화면 제목을 다시 읽기만 하는 줄은 두지 않습니다(예: 휴대폰 결제 방법 화면, 영수증 화면의 ‘영수증을 받으시겠어요?’).
- 화면당 음성은 버튼 위치를 알리는 줄 위주로 둡니다. 노년층이 어려워하는 것은 무엇이 어디에 있는지 찾는 일이라, 버튼마다 한 줄씩 읽고 그 버튼에만 테두리를 두르는 방식은 그대로 둡니다. ‘담은 메뉴를 확인해 주세요’처럼 버튼을 가리키지 않는 줄은 뺍니다(장바구니, 고른 내용 확인, 디저트). 손님이 손해 보지 않게 하는 정보(‘주문번호표는 영수증을 받지 않아도 나와요.’)와 돈·카드 안내는 남깁니다.
- 그래서 화면당 시간에 정해진 상한은 없습니다. 상품(음료) 약 19초, 영수증 약 15초, 메뉴 약 13초, 휴대폰 결제 방법 약 12초는 모든 줄이 버튼 안내라 그대로 둡니다(1초에 4.5자로 읽는다고 잡은 추정값).
- 돈·카드·결제 여부, 경고·오류, 되돌리기 어려운 동작의 확인 창 첫 줄은 줄이지 않습니다.
- ‘기다려 주세요’ 문장들은 상황마다 챙길 것(카드를 빼지 않기, 다음 지폐 기다리기)이 달라 합치지 않습니다.

**늘 같은 숫자 하나**: 이용방법 선택 안내의 ‘개인컵은 음료 한 잔마다 500원이 할인돼요.’는 그대로 읽습니다. 주문마다 바뀌는 금액이 아니라 늘 같은 할인 규칙이고, 손님이 개인컵을 고를지 판단하는 데 필요한 정보이기 때문입니다(2026-10-22 사용자 확인). 음성 검사(`scripts/check-voice-guide.mjs`)도 이용방법 안내만 숫자 검사에서 뺍니다.

### 4.3 고르기 (온도·크기·카페인·얼음)

| 화면 | 고르기 전 | 고른 뒤 |
|---|---|---|
| 온도 | 따뜻하게 드실지, 차갑게 드실지 골라 주세요. | {다음 버튼 이름} 버튼을 눌러 주세요. |
| 크기 | 원하는 크기를 기본, 대, 특대 중에서 골라 주세요. 추가 금액은 각 버튼에 적혀 있어요. | 〃 |

**다음 버튼 이름**: 화면 글자의 ` · `를 쉼표로 바꿔 읽습니다(예: ‘다음 · 크기 선택’ → ‘다음, 크기 선택’).

| 화면 | 버튼 이름 |
|---|---|
| 온도 | 다음, 기본값 확인 · 다음, 크기 선택 |
| 크기 | 다음, 카페인 선택 · 다음, 얼음 선택 · 다음, 선택 확인 |
| 카페인 | 다음, 얼음 선택 · 다음, 선택 확인 |
| 얼음 | 다음, 선택 확인 |
| 선택을 바꾸는 중(확인 화면·장바구니에서 들어옴) | 변경 적용 · 기존 선택 유지 · 다음, 얼음 선택 |

- 고를 것은 버튼 이름 그대로 읽습니다(카페인 있음·디카페인, 얼음 보통·얼음 적게·얼음 없이).
- 고른 뒤에는 버튼 이름이 할 일을 말하므로 이름만 읽습니다(예: 다음, 크기 선택 버튼을 눌러 주세요.).
- 선택을 바꾸는 중의 두 버튼은 장바구니 ‘선택 바꾸기’ 창과 같은 문장으로 읽습니다: ‘바꾼 대로 하려면, 변경 적용을 눌러 주세요.’ / ‘그대로 두려면, 기존 선택 유지를 눌러 주세요.’
- 버튼 이름을 찾지 못하면 ‘아래 버튼을 눌러 주세요.’로 읽습니다.

### 4.4 결제 방법

| 언제 | 읽는 순서 |
|---|---|
| 고르기 전 | ① 결제할 금액은 결제 방법 버튼 위에 있어요.<br>② (쓸 수 없는 방법이 있으면 그 방법마다) {결제 방법}{은/는} 지금 쓸 수 없어요.<br>③ {쓸 수 있는 결제 방법들} 중에서 골라 주세요. |

- 결제 방법: 신용·체크카드, 현금, 모바일 결제. 화면의 ‘현금(지폐)’는 ‘현금’으로 읽습니다.

- 예: 현금 장치가 꺼져 있으면 ② 현금은 지금 쓸 수 없어요. ③ 신용·체크카드, 모바일 결제 중에서 골라 주세요.

## 6. 실제 TTS로 바꿀 때 정할 것

TTS를 만들어 줄 분께 보낼 요청서와 문장 목록은 [`docs/tts/`](tts/TTS-요청서.md)에 있습니다. 문장 목록은 전체(164줄)와 성공 흐름만(54줄, 주문해서 카드·현금·휴대폰으로 결제가 되는 길) 두 가지이며, `npm run voice:tts`로 만들고 `npm run check`가 코드와 같은지 검사합니다.

**진행 순서 (2026-10-28 사용자 결정)**

| 단계 | 할 일 | 상태 |
|---|---|---|
| 1 | 문장 이름표(파일 이름) 정하기 | 완료: 문장 글자로 만든 이름(`src/voice/lineId.ts`, 예: `v_ec8eeca6`). 다른 문장이 바뀌어도 그대로이고, 이 문장을 고치면 이름도 바뀝니다 |
| 2 | 목소리 정하기 | 완료: 여성 목소리, 보통 빠르기(사용자 2026-10-28) |
| 3 | 전체 164줄 요청 | 화면별 문장을 한 줄씩 미리 만든 파일로 받습니다 |
| 4 | 받은 파일 넣기 | 파일 이름이 번호나 문장이면 `node scripts/voice-rename.mjs <받은 폴더>`로 이름표로 바꿔 `public/voice/`에 넣고, `npm run voice:files` 실행. 없는 파일은 브라우저 음성으로 읽으므로 일부만 와도 됩니다 |

**발음 확인이 필요한 말:** 숫자(500원), 가운뎃점이 든 말(신용·체크카드, 바코드·QR), 영문 ‘QR’, 버튼 이름 ‘다음, ○○’

**코드에서 정할 것 (프론트엔드 담당).** 지금은 브라우저 음성 합성이 해 주는 일이라, 녹음 파일로 바꾸면 새로 만들어야 합니다.
- (완료, 2026-10-29) 문장을 차례로 틀기 · 시작 알림(노란 테두리) · 화면이 바뀌면 멈추기 · 음량 · 못 불러온 줄은 브라우저 음성으로 · 화면에 들어올 때 미리 받기 · 이름표(`voiceLineId`)로 파일 찾기 — `speech.ts`, `voiceFiles.ts`
- 실제 기기에서 소리 허용(첫 터치 전 소리 막힘)은 그대로 남은 일입니다
