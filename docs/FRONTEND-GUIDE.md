# 프론트엔드 인계 안내

기준: 2026-10-28. 시연 코드와 Figma에서 확인할 것, 화면만 봐서는 알기 어려운 동작 규칙, 결제(Toss) 연결 지점을 모았습니다.

## 1. 전제

- 매장에 설치하지 않는 시연입니다. 결제는 Toss 테스트 결제를 붙여, 실제로 작동하는 것처럼 보여 줄 예정입니다.
- Toss 연결은 프론트엔드 담당 범위입니다. Toss 창을 어디서 열지, 결과를 화면에 어떻게 이어 붙일지는 담당자와 정합니다. 디자인 쪽은 결과별로 어떤 화면이 나와야 하는지까지 정리했습니다.
- 지금 결제 흐름은 Toss를 붙이기 전의 시뮬레이터입니다. 공개 화면에서는 기계가 처리하는 단계(카드 읽기·현금 세기·출력 등)가 **저절로 진행**돼 조작 없이 끝까지 보입니다. 기기 결과를 직접 고르는 결제 화면 위쪽 `시연:` 버튼은 **`?preview=dev`에서만** 보입니다(실패·오류 결과 확인용).
- Figma 원본은 큰 글씨 보기로 그렸습니다. 시연 사이트와 비교할 때는 주소에 `&large=1`을 붙여 주세요.

**화면 페이지 읽는 법**
- 한 줄이 하나의 흐름입니다(`A1 · 제목`, `B1…`).
- 줄 머리 색: 검정은 기본 흐름, 파랑은 고객이 다른 것을 고를 때, 주황은 문제가 생길 때입니다.
- 점선 상자는 다른 줄로 이어진다는 뜻이고, ‘또는’은 그중 하나라는 뜻입니다.
- 화면 위 이름표는 `번호 · 이름 · 코드 이름` 순서입니다.
- 10·11·12 맨 위의 ‘동작 규칙 · 코드 기준’ 표에는 화면만 봐서는 모르는 규칙과 해당 코드 위치를 적었습니다.

카드(시뮬레이터) 흐름 — `시연:` 버튼을 직접 누르려면 `?preview=dev`가 필요합니다: `?cart=1&screen=method&toss=off&preview=dev` → ‘포장’ → ‘장바구니 보기’ → ‘결제 방법 고르기’ → ‘신용·체크카드’ → ‘카드로 결제하기’ → ‘시연: 카드 삽입 감지’ → ‘시연: 카드 읽기 완료’ → ‘시연: 승인 성공’ → ‘카드를 챙겼어요’ → ‘받기’ 또는 ‘받지 않기’ → ‘시연: 출력 완료’.

### Toss 테스트 결제(카드) — 지금 붙어 있는 것

- **카드만** Toss 테스트 결제창으로 연결돼 있습니다. 현금·모바일은 그대로 `시연:` 버튼 흐름입니다.
- **클라이언트 전용 데모**입니다. 승인(confirm)은 서버가 필요해 호출하지 않습니다 — 결제창 인증 후 성공으로 돌아오면 그대로 ‘결제가 완료됐어요’(카드 회수) 화면을 보여 줍니다. 실제 승인·청구는 일어나지 않습니다. 진짜 end-to-end 승인이 필요하면 서버리스 `confirm` 함수를 붙이는 것이 다음 단계입니다(Figma ‘11·결제’ Q1~Q12).
- **키**: `.env`에 `VITE_TOSS_CLIENT_KEY=test_ck_…`(공개 테스트 클라이언트 키)를 넣습니다. Vercel 프로젝트 환경변수에도 같은 키를 등록합니다. 시크릿 키는 쓰지 않습니다.
- **동작**: ‘카드로 결제하기’를 누르면 현재 주문(장바구니·이용 방법·주문번호·보기 설정)을 `sessionStorage`에 저장하고 Toss 결제창으로 이동합니다. 성공은 `?toss=success`, 실패·취소는 `?toss=fail`로 돌아오며, 앱이 상태를 복원해 완료(`success`) 또는 거절(`declined`) 화면부터 다시 시작합니다. 결과 scene 뒤(영수증·완료)는 기존 흐름 그대로입니다.
- **되돌리기**: 주소에 `?toss=off`를 붙이면 카드도 기존 시뮬레이터로 돌아갑니다(오프라인·키 없는 점검용). 키가 없거나 결제창을 못 열면 자동으로 시뮬레이터로 넘어갑니다.

## 6. 코드 작업 시 참고

- 여백·글자·부품 크기의 원본은 `src/design-system/tokens.json`입니다. 고친 뒤 `npm run tokens:generate`로 CSS를 다시 만듭니다.
- Figma 인계 데이터 `docs/design-system/figma-handoff.json`은 `npm run design:export`로 다시 만듭니다.
- `npm run check`는 위 두 생성 파일이 원본과 같은지, TTS 문장 목록과 녹음 파일 목록이 최신인지, 주문·결제·음성 안내 규칙을 검사합니다.
- 녹음 파일을 받으면 `node scripts/voice-rename.mjs <받은 폴더>`로 이름표로 바꿔 `public/voice/`에 넣고(이름이 이미 이름표면 바로 넣어도 됨) `npm run voice:files`를 실행합니다. 없는 파일 목록이 나오고, 그 줄은 브라우저 음성으로 읽습니다. 배포할 때도 이 검사를 통과해야 게시됩니다.
- 결제 흐름을 바꾸면 `scripts/check-payment-flow.mjs`, `scripts/check-payment-session.mjs`, `scripts/check-voice-guide.mjs`를 함께 고쳐야 합니다.
- 디자인 시스템 구조는 [docs/design-system/README.md](design-system/README.md)를 참고하세요.
