# Color 컬러 시스템

색상은 정보 전달, 사용자 행동 유도, 상태 표현을 위한 핵심 요소로, 정의된 기준에 따라 일관되게 적용합니다.
모든 텍스트와 배경의 조합은 명도 대비 **4.5:1 이상**을 확보합니다. 대비 수치는 WCAG 2.x 기준으로 계산한 값입니다.

브랜드 원색 4개를 기준으로 합니다.

| 이름 | HEX | 성격 |
|---|---|---|
| Gold | `#C5A059` | 황금빛 크레마. 브랜드 분위기를 만드는 색 |
| Red | `#E60013` | 브랜드 상징색. 시선을 잡는 포인트 |
| Brown | `#231916` | 에스프레소. 헤더·푸터·어두운 섹션 (= `primary-95`) |
| Cream | `#FCFCFC` | 기본 배경 |

---

## 60-30-10 배분

화면 면적을 세 역할로 나눕니다. 비율은 면적 기준이며 정확한 수치가 아니라 감각적 기준입니다.

| 비율 | 역할 | 사용 토큰 | 주요 활용 영역 |
|---|---|---|---|
| **60%** | 주조색 Dominant | `gray-0`, `gray-5`, `gray-10`, `gray-100`(검정) | 페이지 배경, 카드 바탕, 입력창 바탕, 본문 텍스트, 헤더·푸터·어두운 섹션 배경 |
| **30%** | 보조색 Secondary | `primary-5`~`primary-30`, `primary-50`(Gold), `primary-95`(Brown) | 섹션 배경, 카드 강조 바탕, 아이콘, 구분선, 검정 배경 위 브랜드 톤 카드 |
| **10%** | 강조색 Accent | `secondary-60`(Red), `secondary-70` | CTA 버튼, 핵심 링크, 선택 상태, 배지, 로고 포인트 |

### 규칙
1. **Red는 10%를 넘기지 않습니다.** 한 화면에 Red CTA는 1개가 원칙입니다. 넓게 쓰면 강조 기능이 사라집니다.
2. **Gold는 면으로 씁니다.** 배경, 아이콘, 구분선, 큰 제목 장식에 쓰고 작은 글자로는 쓰지 않습니다. Gold(#C5A059)와 흰색의 대비는 2.5:1로 기준 미달입니다. 밝은 배경 위 Gold 글자가 필요하면 `primary-60` 이상을 씁니다.
3. **부정(오류) 색은 브랜드 Red와 분리합니다.** 브랜드 Red가 CTA에 쓰이므로 오류까지 같은 Red면 "눌러야 할 것"과 "잘못된 것"이 구분되지 않습니다. 오류는 별도의 Negative 묶음(차가운 크림슨)을 씁니다. 자세한 기준은 Negative 항목 참고.
4. 어두운 배경은 검정 `gray-100`이 기본이고, 그 위에 Brown `primary-95` 카드를 올려 브랜드 톤을 더합니다. 어두운 배경에서는 Gold가 보조색이자 글자색을 겸합니다. Gold와 검정의 대비는 8.5:1, Brown과는 7.0:1입니다. 어두운 배경 위 Red 글자는 3.6:1로 쓰지 않습니다.

## Negative 부정 의미

주의, 경고, 오류 등 문제 상황이나 실패 상태를 사용자에게 안내할 때 사용합니다.

브랜드 Red(`#E60013`, 주황 기운)와 구분되도록 **차가운 크림슨(분홍 기운)**으로 정의합니다. 색상환에서 약 16° 떨어져 있어 나란히 놓으면 다른 색으로 보입니다.

### 브랜드 Red와 오류를 구분하는 3가지 장치
색만으로 구분하면 부족하므로 아래 3가지를 항상 같이 씁니다. 브랜드 색이 빨강인 서비스가 공통으로 쓰는 방법입니다.

1. **아이콘 + 문구를 반드시 붙입니다.** 오류는 색 하나로 표현하지 않습니다. 예: ⚠ 아이콘 + "비밀번호가 틀렸습니다".
2. **형태를 다르게 합니다.** 브랜드 Red는 꽉 찬 면(버튼), 오류는 테두리·밑줄·작은 글자. 예: 오류 입력창은 `negative-70` 1px 테두리 + 아래 `negative-70` 문구.
3. **위치를 고정합니다.** 오류 문구는 항상 입력창 바로 아래, 알림 배너는 항상 화면 상단. 사용자가 위치로 의미를 학습합니다.

- 사용 예: 오류 문구 `negative-70`, 오류 입력창 테두리 `negative-70`, 삭제 버튼 배경 `negative-70` + 흰 글자, 오류 배너 배경 `negative-5` + 글자 `negative-80`
- 삭제 같은 파괴적 행동 버튼은 `negative-70`을 씁니다. `secondary-60`(브랜드 Red)을 쓰면 CTA로 오해합니다.

## 고대비 High Contrast 모드

키오스크의 고대비 모드에서 쓰는 묶음입니다. 저시력·고령 사용자를 위한 것입니다.
**NIA(한국지능정보사회진흥원) 키오스크 UI 가이드의 고대비 값을 그대로 씁니다.** 브랜드 색을 고대비에 맞게 변형하지 않습니다. 고대비 모드에서는 브랜드 표현보다 식별성이 우선이기 때문입니다.

기본 모드와 **구조는 같고 값만 다릅니다.** 같은 토큰 이름에 다른 값을 넣는 방식이므로, 화면을 두 벌 그릴 필요 없이 모드만 바꾸면 됩니다.

### 고대비 모드의 원칙
1. **배경은 어둡게**: 페이지 배경 `gray-100` `#000000`, 글자는 흰색(대비 21:1).
2. **각 묶음의 40단계가 주 사용 컬러**: 모두 검정 글자·검정 배경과 9:1 이상입니다.
3. **버튼은 밝은 면 + 검정 글자**: 기본 모드와 반대입니다. 예: CTA 배경 `hc-primary-40` + 글자 `#000000`.
4. **고대비에는 Secondary(Red) 묶음이 없습니다.** NIA 체계가 primary·positive·negative 3묶음이므로 그대로 따릅니다. 기본 모드에서 Red가 맡던 CTA 역할은 고대비에서 `hc-primary`(노랑)가 맡습니다.
5. **색만으로 의미를 전달하지 않습니다**: 기본 모드보다 더 엄격하게 아이콘·문구·테두리를 함께 씁니다.

## 토큰 이름 규칙

개발자에게 넘길 이름입니다. 피그마 Variables와 코드(CSS 변수)에서 같은 이름을 씁니다.

```
gray-0 … gray-100
primary-5 … primary-95     (Gold)
secondary-5 … secondary-95 (Red)
positive-5 … positive-95
negative-5 … negative-95
hc-primary-5 … hc-negative-95   (고대비 3묶음, NIA 값 그대로)
```

피그마 Variables 경로와의 대응:
- `Color/Gray/40` → `gray-40` (템플릿 값 그대로)
- `Color/Light/primary/50` → `primary-50`
- `Color/HC/primary/40` → `hc-primary-40`
- `Color/Light/secondary` 그룹은 템플릿에 없으므로 **새로 추가**합니다. `Color/HC/*`는 템플릿 값을 그대로 둡니다.

의미 토큰(역할 이름)은 위 단계 토큰을 가리킵니다. 색을 바꿀 때 의미 토큰만 고치면 전체가 바뀝니다.

## 쓰지 말 것

1. 밝은 배경 위 `primary-50` 이하 단계의 글자 (대비 미달)
2. `primary-50` 면 위 흰 글자 (대비 2.5:1)
3. 오류·삭제에 `secondary`(브랜드 Red) 사용 (CTA와 혼동)
4. 한 화면에 `secondary-60` CTA 2개 이상
5. 어두운 배경(`primary-95`, `gray-100`) 위 `secondary-60` 글자 (대비 3.6:1, 4.4:1)
6. 단계 사이의 임의 색 (예: `#C0A050`처럼 표에 없는 값)
