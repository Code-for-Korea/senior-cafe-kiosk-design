### 표시

| 표시 | 뜻 |
|---|---|
| 작은 번호(각주) | 현장 관찰 사례나 기획 결정의 출처 번호입니다. 사례는 본문에 문장으로 쓰고, 번호(관찰 F-05, 기획 D-04 등)는 [문서 맨 아래](#footnotes)에 모았습니다 |
| [설문] | 배리어프리 키오스크 퀴즈(66명) 결과 |
| [기준] | 법령·공공 가이드 같은 외부 기준 |
| [기획] | 기획 문서에서 정한 것. 기획 문서는 공개하지 않았고, 코드 주석에 같은 번호가 있습니다 |
| [디자이너] | 디자이너가 시안을 비교하거나 판단해 정한 것 |
| ※ 시연값 | 실제 매장에서는 바꿔야 하는 임시 값 (예: 주문번호 27번부터) |
| [미정] | 아직 정하지 않은 것 ([7장](#ch7)) |

### 이 문서의 한계

1. **노년층 사용자로 시험하지 않았습니다.** 여기 적은 이유는 "이렇게 하면 나아질 것"이라는 설계 판단이고, 실제로 나아졌다는 증거는 아닙니다.
2. **실제 기기에서 확인하지 않았습니다.** 시연은 1080×1920 화면을 브라우저 크기에 맞춰 줄여 보여 줍니다. 실제 글자 높이·버튼 크기(mm)는 재지 못했습니다.
3. **현장 관찰은 다른 키오스크를 본 기록입니다.** 우리 화면을 본 기록이 아닙니다. 진행자가 옆에서 도와준 상태였고, 참여자의 나이·인원 정보는 없습니다.
4. **퀴즈 응답자는 노년층이지만, 수가 적습니다(66명).** 퀴즈에 나이 문항이 없어 한 사람씩의 나이도 알 수 없습니다. 결과는 참고 자료로만 봐 주세요.

## 1. 용어 풀이

| 용어 | 뜻 |
|---|---|
| **시연** | 실제 서비스가 아니라, 화면과 동작을 직접 눌러 보며 검토하려고 만든 웹페이지입니다. 예시 메뉴 6개가 들어 있습니다 |
| **기능바** | 화면 맨 아래에 늘 있는 버튼 줄입니다. 큰 글씨·고대비·낮은 화면·음성 안내·직원 부르기·처음으로가 있습니다 |
| **보조 줄** | 기능바 바로 아래 줄입니다. 언어 버튼이 있고, 음성 안내를 켜면 '다시 듣기'와 '음량'이 나옵니다 |
| **진행바** | 화면 위쪽에서 지금 몇 단계인지 보여 주는 줄입니다(이용 방법 → 메뉴 → 추가 선택 → 장바구니 → 결제). 누르는 버튼은 아닙니다 |
| **고르기** | 음료의 온도·크기·카페인·얼음을 정하는 일입니다. 화면에서도 '옵션' 대신 '고르다'라고 씁니다 |
| **기본 값으로 주문** | 온도만 고르고, 나머지는 크기 '기본', 카페인 '있음', 얼음 '보통'으로 정해지는 주문입니다 |
| **내 입맛에 맞게 주문** | 온도·크기·카페인·얼음을 하나씩 직접 고르는 주문입니다 |
| **대화상자** | 화면 위에 뜨는 작은 창입니다. 예: "같은 메뉴를 더 담을까요?" |
| **시간 초과** | 한동안 아무것도 누르지 않아 첫 화면으로 돌아가는 일입니다 |
| **고대비** | 검은 바탕에 흰 글자·노란 버튼으로 바꾸는 보기 설정입니다. 눈이 침침하거나 빛 번짐이 있는 사람을 위한 기능입니다 |
| **낮은 화면** | 화면 위쪽을 비우고 버튼을 모두 아래로 내리는 보기 설정입니다. 휠체어 이용자나 키가 작은 아동처럼 눈높이·손 높이가 낮은 사람을 위한 기능입니다 |

## 2. 한눈에 보기

### 2-1. 주문 흐름

```
대기 화면 → 이용 방법 → 메뉴 → 상품 정보 ─┬─ 기본 값으로 주문 ──── (온도) → 고른 내용 확인 ─┐
                                          └─ 내 입맛에 맞게 주문 ─ 온도 → 크기 → 카페인 → 얼음 ┤
                                             디저트: 상품 정보에서 바로 수량 정하고 담기 ──────┤
                                                                                              ↓
                          완료 ← 영수증 고르기 ← 결제 진행(카드·현금·휴대폰) ← 결제 방법 ← 장바구니
```

- 고르기는 그 메뉴에 필요한 것만 묻습니다. 카페인은 커피만, 얼음은 차가운 음료만 묻습니다.
- 메뉴 화면의 '따뜻한 음료' 탭에서 골랐거나 온도가 하나뿐인 메뉴(예: 녹차 스무디)는 온도를 다시 묻지 않습니다.

### 2-2. 관찰한 문제와 우리 설계

현장 관찰 기록(카페 키오스크·무인발권기, 2026-08 작성)에서 카페 주문과 관련된 문제를 골라, 우리 설계와 나란히 놓았습니다.

| 관찰한 문제 | 우리 설계 | 자세히 |
|---|---|---|
| 장바구니에서 메뉴를 더 담는 버튼이 '닫기'라서 찾지 못함[^f05] | 버튼 이름에 할 일을 씀: **'메뉴 더 고르기'**, '← 메뉴', '이전 · 장바구니' | [P1](#p1), [4-7](#s4-7) |
| 옵션 변경 버튼이 글자 없는 연필 아이콘이고, 바로 옆에 삭제(X)가 있음[^f06] | **'선택 바꾸기 ›'** 글자 버튼. 빼기는 **확인 창**을 한 번 더 거침 | [P2](#p2), [P3](#p3), [4-7](#s4-7) |
| 접근성 기능을 아무도 스스로 찾지 못함. 아이콘에 글자가 없고 화면마다 자리가 다름[^f04] | 기능바를 **모든 화면 맨 아래 같은 자리**에 두고 **아이콘마다 글자**를 붙임. 대기 화면에서 먼저 알려 줌 | [P4](#p4), [5-1](#s5-1) |
| 따뜻한 것·차가운 것을 어디서 고르는지 모름[^f08] | 메뉴에 **'따뜻한 음료'·'차가운 음료' 탭**을 두고, 상품을 고른 뒤 **온도부터** 물음. 번호 목록으로 다음 질문을 미리 보여 줌 | [4-3](#s4-3), [4-5](#s4-5) |
| 옵션 화면이 글자뿐이라 "그림이라도 있으면"[^f09] | 온도·크기·카페인·얼음 카드에 **그림**을 넣음(크기마다 컵 높이, 얼음 개수가 다름) | [4-5](#s4-5) |
| 매장이 '디카페인은 메뉴 선택 후 다음에 있습니다' 스티커를 붙임[^f15] | 고르기 단계를 **번호 목록**으로 보여 줘, 카페인을 어디서 고르는지 미리 알 수 있게 함 | [4-5](#s4-5) |
| 목록을 넘기는 방법이 안 보임[^f11] | **'아래로 내리면 메뉴가 더 보여요 ↓'** 안내와 아래쪽 그림자 | [4-3](#s4-3) |
| 뒤에 선 줄 때문에 조작을 포기함[^f14]. 법정 기준은 남은 시간을 보여 주라고 함 | 90초 동안 안 누르면 **"아직 주문 중이시죠?"** 창에 **남은 초**를 보여 주고, '계속 주문하기'로 시간을 늘림 | [P6](#p6), [6장](#ch6) |
| 고대비가 청록색이라 노안에 효과가 낮음[^f03] | 고대비는 **검정 바탕 + 흰 글자 + 노란 버튼** | [5-3](#s5-3) |
| 휠체어 높이 조절 버튼이 동작하지 않음[^f01] | **낮은 화면**: 위쪽을 비우고 모든 버튼을 아래로 | [5-4](#s5-4) |
| 카드를 어디에, 얼마나 깊이 넣는지 모름("끝까지 넣어주세요")[^f10] | 결제 화면에 **카드가 들어가는 움직이는 그림 + 큰 화살표** | [4-9](#s4-9) |

**퀴즈 결과에서 나온 설계**

| 퀴즈 결과 | 우리 설계 |
|---|---|
| 자유 응답 22건 중 "글자가 작다"가 8건으로 가장 많음 | **큰 글씨** 설정. 큰 글씨에서 본문을 36으로 올린 곳들([5-2](#s5-2)) |
| 34.8%가 직원 호출을 "음성·화상으로 직원과 이야기하는 것"으로 잘못 앎(틀린 사람은 모두 이 답을 고름) | 직원 호출 창에 **"이 자리에서 잠시 기다려 주세요"**와 **호출 위치**를 씀([6장](#ch6)) |
| 음료 크기 외래어(톨·벤티) 정답률 68.2% | 크기를 **기본·대·특대**로 부름([4-5](#s4-5)) |
| 키오스크 외래어(테이크아웃·투고 등) 정답률 66.7% | 이용 방법을 **매장이용·포장·개인컵**으로 부름([4-2](#s4-2)) |

## 3. 공통 원칙

<a id="p1"></a>
### P1. 버튼 이름에 할 일을 쓴다

- **규칙**: 버튼 이름에 무엇을 하는지, 어디로 가는지를 씁니다. '닫기', '확인'처럼 누른 뒤 어떻게 될지 모르는 이름은 피합니다.
- **예**: '메뉴 더 고르기', '← 메뉴', '이전 · 장바구니', '다음 · 크기 선택', '6,100원 담기', '카드로 결제하기'
- **이유**: 누르기 전에 결과를 알 수 있어야 합니다. 관찰에서 '닫기' 버튼을 보고 "이거 닫기? … 어떻게 하라는 거야 여기서?"라고 되묻는 장면이 있었습니다.[^f05]

<a id="p2"></a>
### P2. 아이콘에는 글자를 붙인다

- **규칙**: 기능바의 아이콘 아래에는 모두 이름을 씁니다. 장바구니에서 고른 내용을 바꾸는 버튼도 연필 아이콘이 아니라 '선택 바꾸기 ›' 글자입니다.
- **이유**: 아이콘 모양만으로는 기능을 짐작하기 어렵습니다. 관찰에서 참여자가 접근성 기능을 스스로 찾은 경우는 한 번도 없었습니다.[^f04] [^f06]
- **예외**: 장바구니 카드의 빼기(×)는 글자가 없습니다. 대신 누르면 확인 창이 뜹니다(P3).

<a id="p3"></a>
### P3. 되돌리기 어려운 동작은 한 번 더 묻는다

- **규칙**: 장바구니에서 메뉴 빼기, 처음으로 가기, 고르던 내용을 버리고 메뉴로 가기, 바꾼 내용 취소는 확인 창을 띄웁니다. 확인 창의 왼쪽은 '그만두기', 오른쪽은 '하려던 일'입니다.
- **예**: "아메리카노를 장바구니에서 뺄까요? / 고른 내용과 수량도 함께 지워져요." — '아니요' | '빼기'
- **이유**: 잘못 눌러 메뉴가 사라지지 않게 합니다. 관찰에서 메뉴를 더 담으려던 사람이 옵션 변경 버튼을 잘못 누른 일이 있었습니다.[^f06] 다만 관찰된 것은 '옵션 변경'을 잘못 누른 일이고, '삭제'를 잘못 누른 일은 관찰되지 않았습니다.
- **예외**: 품절 메뉴의 '빼기'는 묻지 않고 바로 뺍니다. 어차피 주문할 수 없기 때문입니다.

<a id="p4"></a>
### P4. 같은 기능은 늘 같은 자리에 둔다

- **규칙**: 기능바는 모든 화면 맨 아래에 있습니다. 음성 안내의 '다시 듣기'와 '음량'은 늘 그 아래 줄에 있고, 대화상자가 열려도 같은 자리에 있습니다.
- **이유**: 한 번 찾은 기능을 다음 화면에서 다시 찾지 않게 합니다. 관찰한 키오스크는 접근성 아이콘이 대기 화면에서는 아래 가운데, 메뉴 화면에서는 위 오른쪽에 있었습니다.[^f04] 기획에서도 다시 듣기와 음성 안내 끄기를 늘 같은 자리에 두기로 했습니다.[^d04] 예전 시안은 다시 듣기 자리가 화면마다 네 군데로 달랐습니다.

<a id="p5"></a>
### P5. 막다른 화면을 만들지 않는다

- **규칙**: 기다리거나 실패한 화면에도 할 수 있는 일을 하나 이상 둡니다.
  - 메뉴를 10초 안에 못 불러오면 → '다시 불러오기'와 직원 부르기 안내
  - 조건에 맞는 메뉴가 없으면 → '전체 메뉴 보기'
  - 장바구니가 비면 → '메뉴 보러 가기'
- **이유**: 끝나지 않는 기다림이나 아무것도 할 수 없는 화면에 손님을 두지 않습니다. [디자이너]

<a id="p6"></a>
### P6. 시간에 쫓기지 않게 하고, 남은 시간은 보여 준다

- **규칙**
  - 90초 동안 아무것도 누르지 않으면 "아직 주문 중이시죠?" 창을 띄우고 30초 동안 남은 초를 보여 줍니다. '계속 주문하기'를 누르면 처음부터 다시 셉니다.
  - 결제가 끝난 화면은 저절로 넘어가지만, 남은 초를 늘 보여 주고 화면을 누르면 다시 셉니다. 단, **출력이 실패한 화면**은 손님에게 남은 기록이 화면의 주문번호뿐이라 말없이 넘어가지 않고, 주문 화면과 같은 90초 + 경고 30초를 따릅니다.
  - 돈·카드·출력물이 기계에 걸려 있는 화면은 시간 초과로 넘어가지 않습니다. 카드가 꽂혀 있을 수 있는 화면(카드 읽기 실패·거절)은 시간 초과가 있되, 경고 창에서 "꽂혀 있는 카드를 꺼내 주세요."라고 먼저 알립니다.
  - 직원을 부르면 시간을 세지 않습니다. 직원이 90초 안에 오지 않으면 다시 셉니다.
  - 경고 창은 넘어가면 무엇을 잃는지 알려 줍니다. 주문 화면은 장바구니, 출력 실패 화면은 주문번호, 카드 화면은 꽂힌 카드입니다.
- **이유**: 시간에 쫓기면 포기하게 됩니다. 관찰에서 뒤에 선 줄 때문에 과제를 건너뛴 사람이 있었습니다.[^f14] 반대로 한 사람이 너무 오래 멈춰 있으면 뒤에 기다리는 사람이 곤란하고, 손님이 떠난 뒤 주문 내용이 다음 손님에게 보여서도 안 됩니다. 그래서 한없이 기다리지 않고, 한 번 물어본 뒤 첫 화면으로 돌아갑니다.
- **근거**: [기준] 검증기준 2.b "부득이하게 시간제한을 두는 경우, 화면에 남은 제한시간을 표시". 완료 화면 20초는 기획 결정입니다.[^d13]
- **90초·30초**: 평균적인 조작 시간을 생각해 정한 값입니다. [디자이너] 이를 뒷받침하는 측정값은 없어서 실제 이용자로 확인해야 합니다([8장 질문 9](#ch8)).

<a id="p7"></a>
### P7. 확인하지 못한 것은 확인한 것처럼 말하지 않는다

- **규칙**
  - 직원을 불러도 "직원이 오고 있어요", "접수됐어요"라고 쓰지 않고 "직원 도움을 기다리고 있어요"라고 씁니다.
  - 결제가 됐는지 모를 때는 "결제 여부를 확인하지 못했어요 / 다시 결제하지 말고 직원에게 확인을 요청해 주세요"라고 쓰고, 다시 결제하는 버튼을 두지 않습니다.
  - 결제가 안 된 것이 확실할 때만 "결제되지 않았어요"라고 쓰고 다른 결제 방법을 고르게 합니다.
- **이유**: 확인하지 못한 상태를 확정처럼 보여 주면 손님이 잘못 판단합니다. 결제 여부를 모르는 채 다시 결제하면 두 번 결제될 수 있습니다. [디자이너]

<a id="p8"></a>
### P8. 다음 손님은 처음 상태에서 시작한다

- **규칙**: '처음으로', 시간 초과, 주문 끝으로 새 주문이 되면 장바구니와 고른 내용을 지웁니다. 큰 글씨·고대비·낮은 화면과 음성 안내는 끄고, 음량은 5, 언어는 한국어로 되돌립니다.
- **이유**: 다음 손님이 앞사람의 설정이나 소리 크기를 그대로 쓰지 않게 합니다. [기획]
- 예전에는 큰 글씨로 시작했는데, 2026-10-21부터 기본 글씨로 시작합니다.

<a id="p9"></a>
### P9. 글자를 줄이기 전에 배치를 바꾼다

- **규칙**
  - 화면이 꽉 차도 글자 크기나 목록 간격을 줄이지 않습니다. 대신 스크롤하게 하고, 스크롤할 수 있다고 알려 줍니다.
  - 버튼의 중요도는 크기가 아니라 채움·테두리·색으로 나눕니다. 같은 자리에 오는 버튼은 높이·둥글기·글자 크기를 맞춥니다.
- **이유**: 따뜻한 음료 화면만 간격을 줄였더니 다른 화면과 목록 모양이 달라졌습니다. 그래서 스크롤을 문제로 보지 않고, 일부 화면만 간격을 줄이는 예외도 두지 않기로 했습니다. [디자이너]

<a id="ch4"></a>
## 4. 화면별 설계

화면마다 **하는 일 → 풀려는 문제 → 요소별 설계 → 동작 규칙** 순서로 적었습니다.

<a id="s4-1"></a>
### 4-1. 대기 화면

**하는 일**: 손님이 다가와 주문을 시작합니다.

**풀려는 문제**
- 어디를 눌러야 시작하는지 몰라 머뭇거립니다.
- 글씨 크기·음성 같은 도움 기능이 있는지 모릅니다. 관찰에서 접근성 기능을 스스로 찾은 사람이 없었습니다.[^f04]

**요소별 설계**

| 요소 | 설계 | 이유 |
|---|---|---|
| 시작 방법 | 시작 버튼이 따로 없고, **화면 아무 곳이나** 누르면 이용 방법 화면으로 갑니다 | [디자이너]<br>① **시작 버튼을 찾지 않아도 됩니다.** 화면 전체가 버튼이라 시력이 약하거나 손이 떨려도 어디를 누르든 시작됩니다.<br>② **눌렀는데 아무 일도 없는 곳이 없습니다.** 관찰한 무인발권기는 표 이름을 눌러도 반응이 없었습니다. 눌렀는데 아무 일도 없으면 사람은 자기가 잘못 눌렀다고 생각하기보다 기계가 고장 났거나 자기 손이 문제라고 여겨, 다시 누르기를 망설입니다.[^f17]<br>③ **잘못 시작해도 손해가 없습니다.** 광고가 한 장뿐이라 광고를 보려고 누를 일이 적고, 잘못 시작해도 '처음으로'나 시간 초과로 돌아옵니다.<br>기획에는 광고와 시작 버튼을 나누는 안이 있었습니다. 이 결정의 단점("광고를 보려고 누른 사람도 주문이 시작됨")은 ③으로 보완합니다 |
| 큰 안내 | "화면을 누르면 주문 시작" | 화면 전체가 버튼이라는 것(①), 어디를 눌러도 반응한다는 것(②)을 처음부터 알려 줍니다 |
| 도움 기능 안내 | "글씨 크기·음성 안내는 아래에서 바꿀 수 있어요" | 주문을 시작하기 전에 도움 기능이 어디 있는지 알려 줍니다[^f04] |
| 누름 표시 | 점 둘레로 물결 두 겹이 2.4초마다 천천히 퍼집니다. 깜빡이지 않습니다 | [디자이너] 기기에서 '움직임 줄이기'를 켜면 멈춥니다 |
| 광고 문구 | 메뉴 이름을 넣지 않습니다 | 사진 속 음료가 메뉴판에 없기 때문입니다 |
| 첫 음성 | 음성 안내가 꺼져 있어도 이 화면에 올 때마다 한 번 말합니다: "화면 아무 곳이나 누르면 주문이 시작돼요. 음성 안내가 필요하면 아래 음성 안내를 눌러 주세요." | [기획] |

**동작 규칙**
- 기능바는 주문 전에도 쓸 수 있고, 눌러도 주문이 시작되지 않습니다. '처음으로'는 흐리게 잠깁니다.
- 이 화면만 시간 초과가 없습니다.
- 브라우저는 첫 터치 전에 소리를 막을 수 있어서, 실제 기기에서는 소리를 허용하도록 설정해야 합니다.

<a id="s4-2"></a>
### 4-2. 이용 방법

**하는 일**: 매장에서 먹을지, 가지고 갈지, 개인컵을 쓸지 고릅니다.

**풀려는 문제**: '테이크아웃', '투고' 같은 외래어를 잘 모릅니다. [설문] 키오스크 외래어 문항 정답률이 66.7%였습니다.

**요소별 설계**

| 요소 | 설계 | 이유 |
|---|---|---|
| 질문 | "어디에서 드시겠어요?" / "이용 방법을 선택하면 메뉴로 이동해요." | 고르면 어떻게 되는지 미리 알려 줍니다(P1) |
| 카드 3장 | **매장이용** "매장에서 먹기" / **포장** "가지고 가기" / **개인컵** "음료 500원 할인, 개인컵 필요" | 외래어 대신 우리말과 풀이를 함께 씁니다. 아이콘은 기기마다 모양이 다른 이모지 대신 선 아이콘을 씁니다 |
| 고르면 바로 이동 | 확인 버튼 없이 바로 메뉴로 갑니다 | 장바구니에서 언제든 '바꾸기'로 고칠 수 있습니다 |

**동작 규칙**
- 처음 값은 '매장이용'입니다.
- **개인컵 할인**: 음료 한 잔마다 기본 가격에서 500원을 뺍니다. 디저트는 할인하지 않습니다. 크기 추가금은 할인한 뒤에 더합니다. 메뉴·검색·상품·장바구니의 가격이 모두 할인된 가격으로 나옵니다.
- 개인컵으로 결제하려 하면 먼저 "결제 후 개인 컵을 카운터에 가져다주세요." 창이 뜹니다('장바구니로' | '확인하고 결제하기'). 완료 화면에도 같은 할 일이 나옵니다.
- 음성 안내는 숫자를 읽지 않는 것이 원칙이지만, "개인컵은 음료 한 잔마다 500원이 할인돼요."는 읽습니다. 주문마다 바뀌는 금액이 아니고, 개인컵을 고를지 정하는 데 필요하기 때문입니다.

<a id="s4-3"></a>
### 4-3. 메뉴

**하는 일**: 주문할 메뉴를 찾아 고릅니다.

**풀려는 문제**
- 따뜻한 것·차가운 것을 어디서 고르는지 모릅니다. 관찰에서 "아까 아이스가 밖에 따로 있는 줄 알았어요."라는 말이 나왔습니다.[^f08]
- 목록을 넘길 수 있다는 것을 모릅니다. 관찰에서 진행자가 손동작을 고쳐 줘야 했습니다.[^f11]
- 메뉴를 눌렀을 때 제대로 눌렸는지 알 수 없으면 불안합니다.

**요소별 설계**

| 요소 | 설계 | 이유 |
|---|---|---|
| 첫째 줄 탭 | 전체 / **따뜻한 음료** / **차가운 음료** / 디저트 | 온도를 메뉴에서도 고를 수 있게 합니다. 관찰자는 메뉴를 아예 온도별로 나누자고 했습니다.[^f08] 우리는 메뉴를 온도로 완전히 나누지 않고, 온도 탭과 상품 다음의 온도 질문을 함께 둡니다 |
| 둘째 줄 칩 | 모든 종류 / 커피 / 차·티 / 스무디 (디저트는 조각케이크 등). **메뉴가 없는 종류는 숨깁니다** | 칩이 보이면 메뉴가 있을 거라고 기대합니다. 눌렀는데 빈 화면이 나오면 헛걸음이 됩니다. 칩 수가 줄어 고르기도 쉬워지고, "조건에 맞는 메뉴가 없어요" 화면도 거의 생기지 않습니다. [디자이너] |
| 메뉴 카드의 온도 | 아이콘 + '따뜻한'·'차가운' 글자. 바탕 없이 둠 | 둥근 바탕을 넣으면 누르는 칩처럼 보입니다. 온도 탭에서는 그 온도만 보여 줍니다 |
| 누름 표시 | 메뉴를 누르면 0.3초 동안 눌린 모양을 보여 준 뒤 넘어갑니다. 그동안 다른 메뉴는 눌리지 않습니다 | 내가 고른 메뉴가 제대로 눌렸는지 보여 줍니다. [디자이너] 두 번 눌리는 일도 막습니다 |
| 스크롤 안내 | "아래로 내리면 메뉴가 더 보여요 ↓"와 아래쪽 그림자. 한 번 내리면 글자가 사라지고, 끝까지 내리면 그림자도 사라집니다 | 아래에 메뉴가 더 있다는 것과 넘기는 방법을 화면에 씁니다.[^f11] |
| 장바구니 막대 | 담은 메뉴가 있을 때만 "장바구니 보기 · N개 · X원" | 비어 있을 때는 그 자리를 메뉴 목록에 씁니다 |

**동작 규칙**
- 디저트는 '전체 · 모든 종류'에서만 음료와 함께 나옵니다.
- 탭이나 칩을 바꾸면 목록이 맨 위로 돌아갑니다.
- **품절**: 사진이 흑백이 되고 가운데에 '품절'이 붙으며, 누를 수 없습니다. 못 고르는 메뉴를 바로 알아보게 합니다. [기획]
- **불러오는 중**: 회색 빈 카드와 "메뉴를 불러오고 있어요"를 함께 보여 줍니다. 회색 칸만 있으면 고장 난 것처럼 보이기 때문입니다. 메뉴가 없으면 찾을 수도 없으므로, 이때는 검색을 잠급니다.
- **못 불러옴**: 10초가 지나면 "메뉴를 불러오지 못했어요"와 '다시 불러오기'를 보여 줍니다(P5). 10초는 ※ 시연값입니다.
- **조건에 맞는 메뉴 없음**: "조건에 맞는 메뉴가 없어요"와 '전체 메뉴 보기'를 보여 줍니다.
- 메뉴 화면에는 이용 방법으로 돌아가는 버튼이 없습니다. 이용 방법은 장바구니에서 바꿉니다.

<a id="s4-3a"></a>
### 4-3a. 메뉴 검색

**하는 일**: 메뉴 이름으로 찾습니다.

| 요소 | 설계 | 이유 |
|---|---|---|
| 한 곳에 모으기 | 입력칸 · 찾은 메뉴 · 자판을 아래 창 한 곳에 모읍니다 | 눈을 멀리 옮기지 않아도 됩니다 |
| 자판 | 휴대폰과 같은 천지인 자판 | 어르신이 휴대폰에서 오래 써 와서 가장 익숙한 자판입니다. [디자이너] |
| 첫소리로 찾기 | 'ㅋㅍ'만 눌러도 '카페라떼'가 나옵니다. 글자를 다 완성하기 전에도 찾아집니다 | 받침·모음까지 정확히 치지 않아도 됩니다 |
| 결과 칸 높이 | 결과 칸은 늘 세 줄 높이입니다. 많으면 두 개만 보이고 "메뉴가 N개 더 있어요. 글자를 더 입력해 주세요."가 나옵니다 | 글자를 치는 동안 자판이 움직이지 않습니다 |
| 고르기와 넘어가기 | 결과를 누르면 선택만 되고, 아래 '주문으로 넘어가기'를 눌러야 넘어갑니다 | 잘못 누른 메뉴로 바로 넘어가지 않습니다 |
| 닫기 | '닫기' 버튼으로만 닫힙니다. 바깥 어두운 곳을 눌러도 닫히지 않습니다 | 검색 창을 닫으면 친 글자가 지워집니다. 손이 떨려 바깥을 스치기만 해도 글자가 다 사라지는 일을 막습니다. 다른 창들도 모두 바깥을 눌러서는 닫히지 않습니다. [디자이너] |

- 품절 메뉴도 결과에 나오지만, 가격 자리에 '품절'이 보이고 고를 수 없습니다.
- 검색으로 들어가면 온도를 정하지 않은 채 상품 화면으로 갑니다.

### 4-4. 상품 정보

**동작 규칙**
- **묻지 않는 단계**: 온도가 하나뿐이거나 메뉴 탭에서 이미 고른 경우 온도를 묻지 않습니다. 카페인은 커피만, 얼음은 차가운 음료만 묻고, 스무디는 얼음을 묻지 않습니다.
- **기본 값**: 크기 기본, 카페인 있음, 얼음 보통(차가운 음료만). 온도는 기본 값이 없어서, 직접 고르거나 메뉴 탭에서 이어받습니다.
- **온도를 바꾸면**: 크기·카페인은 그대로 두고 얼음만 지웁니다. 다시 차갑게 하면 얼음을 새로 고릅니다.
- **목록 간격**: 항목 사이 48, 끝 32로 모든 화면이 같습니다. 화면이 넘치면 스크롤합니다(P9).
- **확인·바꾸기 화면의 미세 스크롤 방지**: 제목(또는 '선택을 바꾸고 있어요' 안내)과 단계 목록 사이 16, 스크롤 끝 여백 16으로 두어 네 단계가 한 화면(기본·큰 글씨)에 들어갑니다. 전에는 24·32라 7~24px만 넘쳐 스크롤이 생겼습니다. 진행바 묶음과 안내 사이는 24 그대로라, 확인 화면과 바꾸기 화면의 목록 첫 줄 위치가 같습니다. 제목 줄 높이를 68로 고정해(글꼴 비율로는 67.2·70) 첫 줄이 기본·큰 글씨 모두 508(4단위)에 놓입니다(2026-11-03).

<a id="s4-6"></a>
### 4-6. 고른 내용 확인

**하는 일**: 고른 내용을 확인하고, 필요하면 바꾸고, 수량을 정해 담습니다.

**풀려는 문제**
- 잘못 고른 것을 담은 뒤에야 알게 됩니다.
- 바꾸다 보면 원래 무엇을 골랐는지 잊습니다.

**요소별 설계**

| 요소 | 설계 | 이유 |
|---|---|---|
| 질문 | 기본 값 그대로면 "기본값으로 담을까요?", 아니면 "선택한 내용이 맞나요?" / "바꿀 내용이 있으면 각 항목의 '바꾸기'를 눌러 주세요." | |
| 바꾸기 화면 | "선택을 바꾸고 있어요." / "'기존 선택'은 바꾸기 전에 고른 것이에요." 원래 고른 카드에 '기존 선택' 표시 | 원래 값을 기억하지 않아도 됩니다 |
| 바뀐 표시 | 바꾼 줄에 '변경'과 "이전: 따뜻하게". 새로 생긴 얼음 줄에는 '새로 선택' | 여러 번 바꿔도 처음 확인 화면에 왔을 때의 값과 비교합니다 |
| 바꾸기 버튼 이름 | 바뀐 것이 있으면 '변경 적용', 없으면 '기존 선택 유지' | 누르면 어떻게 되는지 버튼이 알려 줍니다(P1) |
| 위치 고정 | '바꾸기'를 눌러도 위쪽 목록이 움직이지 않습니다 | 예전에는 위쪽이 72~154px 움직였습니다. [디자이너] |
| 수량 | − 1 + (1~9개), "4,700원 × 2개" | 계산식 대신 "1개 가격 × 개수"로 적습니다 |

**동작 규칙**
- **담기는 이 화면에서만 켜집니다.** 고르기 화면에서는 금액만 미리 보이고, 마지막 질문 뒤 '다음 · 선택 확인'을 눌러 이 화면에 와야 담을 수 있습니다.
- 고르기만 해서는 저장되지 않고, '변경 적용'을 눌러야 저장됩니다.
- 바꾸다가 '취소'를 누르면, 바뀐 것이 있을 때만 "변경을 취소하시겠어요? / 지금 바꾼 내용은 저장되지 않아요."라고 묻습니다.
- 따뜻하게를 차갑게로 바꾸면 얼음까지 고른 뒤에 저장합니다.
- 장바구니에 똑같이 고른 메뉴가 있으면 담을 때 확인 창이 뜹니다([4-7](#s4-7)).

<a id="s4-7"></a>
### 4-7. 장바구니

**하는 일**: 담은 메뉴를 확인하고, 고친 뒤 결제로 갑니다.

**풀려는 문제**
- 결제 직전에 메뉴를 더 담는 방법을 찾지 못합니다. 관찰에서 케이크를 더 담으려던 참여자는 매번 진행자의 도움을 받아야 했습니다.[^f05]
- 옵션 변경 버튼이 무엇인지 모르고, 삭제 버튼과 붙어 있어 잘못 누를 수 있습니다.[^f06]
- 담겼는지 확신하지 못하고, 큰 글씨에서는 방금 담은 메뉴가 화면 밖에 있습니다.

**요소별 설계**

| 요소 | 설계 | 이유 |
|---|---|---|
| 메뉴 더 담기 | **'메뉴 더 고르기'** 버튼을 결제 버튼 옆에 둡니다 | 메뉴를 더 담는 버튼과 결제 버튼을 둘 다 쉽게 찾게 합니다.[^f05] |
| 고른 내용 바꾸기 | 연필 아이콘 대신 **'선택 바꾸기 ›'** 글자. 화면 전체에서 '옵션' 대신 '고르다'를 씀 | 무엇을 하는 버튼인지 글자로 알려 줍니다.[^f06] '옵션'은 낯선 말입니다. [디자이너] |
| 여러 잔이 함께 바뀜 | 2개 이상이면 "아메리카노 · 2개 모두 함께 바뀌어요" | 어디까지 바뀌는지 알려 줍니다 |
| 빼기 | 카드의 ×를 누르면 "○○를 장바구니에서 뺄까요?" 확인 창. 여러 개는 '여러 개 빼기 ›'로 골라서 뺌 | P3 |
| 담기 알림 | 담으면 3초 동안 "○○를 담았어요"와 고른 내용·수량을 보여 줍니다. 누르면 바로 닫히고, 닫히면 담은 줄이 보이게 내려갑니다 | 담았다는 것을 알려 주고, 담은 줄을 찾아 내리지 않아도 되게 합니다. 읽을 시간을 주려고 1.5초에서 3초로 늘렸습니다. 기획에서도 "초 단위로 사라지면 노년층에게 도움이 되지 못한다"고 정했습니다.[^d17] |
| 같은 메뉴 다시 담기 | "같은 메뉴를 더 담을까요? / 장바구니에 똑같이 고른 메뉴가 1개 있어요. / 더 담으면 모두 2개가 돼요." — '담지 않기' \| '더 담기' | 말없이 합치지 않고 묻습니다. 메뉴 이름과 옵션을 다 쓰면 길어서 "똑같이 고른"으로 줄였습니다. [디자이너] |
| 수량 단위 | 음료도 디저트도 **'개'** | 음료와 디저트가 섞인 합계는 어차피 '개'로 셀 수밖에 없습니다 |
| 가격 표기 | 줄마다 그 줄의 금액, 아래에 "총 N개"와 합계 | 계산식(5,500원 × 2)보다 금액의 뜻을 적는 쪽이 낫다고 봤습니다(앱 20개 조사) |
| 이용 방법 바꾸기 | 위쪽 "이용 방법 포장 · 바꾸기 ›" | 처음 화면으로 돌아가지 않고 고칠 수 있습니다 |

**동작 규칙**
- 한 메뉴는 9개까지 담을 수 있습니다.
- '선택 바꾸기'로 바꾼 결과가 다른 줄과 똑같아지면, 같은 창 안에서 "같은 메뉴와 합칠까요?"라고 묻습니다. 합치면 고친 줄이 자리에 남고 다른 줄이 사라집니다. 줄 하나가 말없이 사라지면 헷갈리기 때문에 묻습니다.
- **품절**: 담은 뒤 품절된 메뉴는 맨 위 "주문할 수 없는 메뉴 N개" 칸에 모읍니다. 뺄 때까지 결제 버튼이 잠깁니다. 저절로 빼지는 않습니다.
- **비었을 때**: "장바구니가 비어 있어요"와 '메뉴 보러 가기'를 보여 줍니다. 같은 일을 하는 버튼이 둘이 되지 않게, 이때는 아래 '메뉴 더 고르기'를 숨깁니다.
- 결제 버튼: "13,000원 · 결제 방법 고르기"

**남은 질문**: × 버튼이 카드 위 모서리에 있습니다. 예전 검토에서 "빼기 버튼이 위 모서리에 오는 안은 피하고 싶다"고 적었는데, 지금 위치를 다시 판단한 기록은 없습니다. 지금은 확인 창으로 보완합니다([8장 질문 4](#ch8)).

<a id="s4-8"></a>
### 4-8. 결제 방법

**하는 일**: 결제 금액을 확인하고 결제 방법을 고릅니다.

| 요소 | 설계 | 이유 |
|---|---|---|
| 방법 3가지 | 신용·체크카드 / 현금(지폐) / 모바일 결제 | |
| 결제 버튼 | 고른 방법에 따라 '카드로 결제하기', '현금으로 결제하기', '모바일로 결제하기' | P1 |
| 금액 내역 | "결제 금액 확인 ›"을 누르면 메뉴별 금액을 봅니다 | |
| 쓸 수 없는 방법 | 숨기지 않고 **회색으로 잠근 뒤 "지금 쓸 수 없어요"**라고 씁니다 | [기획][^d19] 칸 아래에 한 줄로 쓰는 안은 잠긴 칸과 떨어지고 버튼을 밀어내서 고르지 않았습니다 |
| 돌아가기 | '이전 · 장바구니' | P1 |

**동작 규칙**
- 결제 도중 기기 문제가 난 방법은 이번 주문 동안 잠깁니다. 직원이 고치면 풀립니다.
- 결제 방법을 고르는 동안 담은 메뉴가 품절되면 장바구니로 돌아갑니다.

<a id="s4-9"></a>
### 4-9. 결제 진행 (카드 · 현금 · 휴대폰)

**하는 일**: 기계에 카드·지폐·휴대폰을 대고 결제를 마칩니다.

**풀려는 문제**
- 카드를 어디에, 얼마나 깊이 넣는지 모릅니다. 관찰에서 "투입구가 좀 애매한데"라는 말이 나왔고, 진행자는 "끝까지 넣어주세요"를 되풀이해야 했습니다.[^f10]
- 기계가 처리하는 동안 다른 버튼을 누르면 화면이 바뀌거나 처음으로 갈 수 있습니다.
- 문제가 생겼을 때 돈이 나갔는지 알 수 없습니다.

| 요소 | 설계 | 이유 |
|---|---|---|
| 카드 넣기 그림 | 카드가 투입구로 들어가는 움직임이 3초마다 되풀이되고, 큰 위쪽 화살표가 있습니다. "금색 칩이 위로 보이도록 넣어 주세요." | 예전에는 멈춘 그림뿐이었습니다. 기획에서 큰 화살표·카드 방향·깊이를 보여 주라고 했습니다. 깜빡이지 않고 그림 칸 안에서만 움직입니다. 투입구 불빛은 기기마다 자리가 달라 넣지 않았습니다 |
| 처리 중 잠금 | 기계가 처리하는 동안 기능바에서 **'직원 부르기'만** 누를 수 있습니다 | [기획][^d20] 잘못 눌러 화면이 바뀌거나 처음으로 가지 않게 합니다 |
| 화면 안 직원 버튼 | 문제 화면 5곳(기기 문제, 결제 여부 모름, 현금 마무리 실패, 영수증 출력 실패, 주문번호표 출력 실패)에만 둡니다. 다른 화면에서는 기능바 버튼을 씁니다. 현금 마무리 실패 가운데 **넣은 돈이 모두 나온 화면**은 돈이 걸려 있지 않아 직원 버튼 없이 '돈을 챙겼어요 · 결제 방법 다시 고르기' 하나만 둡니다(2026-10-29) | 직원 버튼이 화면 안과 기능바에 하나씩 보여, 두 번 불러야 하는 것처럼 보였습니다. [디자이너] |
| 결제 여부 모름 | "결제 여부를 확인하지 못했어요 / 다시 결제하지 말고 직원에게 확인을 요청해 주세요." 직원 부르기만 둡니다 | 두 번 결제되지 않게 합니다(P7) |
| 결제 안 된 기기 문제 | "결제되지 않았어요." 다른 결제 방법이 남아 있으면 '결제 방법 다시 고르기'도 둡니다 | 결제가 안 된 것이 확실한데 직원 부르기만 있으면 손님이 기다리기만 해야 합니다 |
| 결제 방법으로 돌아가기 | 카드 넣기·휴대폰 방법 고르기·현금 넣기 전·카드 실패·거절·기기 문제 화면 모두 **'결제 방법 다시 고르기'** 한 이름입니다. 현금을 넣은 뒤에는 '결제 취소'를 눌러 돈을 먼저 돌려받고, 넣은 돈을 모두 돌려받은 화면은 '돈을 챙겼어요'(돌려받은 돈 회수) 또는 '돈을 챙겼어요 · 결제 방법 다시 고르기'(현금 마무리 실패 · 전액 반환)를 누르면 결제 방법 화면으로 갑니다 | 같은 일을 하는 버튼이 화면마다 '결제방법 변경', '← 이전 · 결제방법 다시선택', '결제방법 다시 선택', '결제 취소'로 달랐습니다(P1, P4). [디자이너] |
| 현금 금액 줄 | 결제할 금액 / 넣은 금액 / 남은 금액. 큰 글씨에서 36 | 지폐를 넣을 때마다 남은 돈을 확인할 수 있습니다 |
| 휴대폰 결제 | "바코드·QR 보여주기"와 "휴대폰 대기" 중에서 고릅니다. "결제 코드 여는 방법 ›"에서 네이버페이·카카오페이·토스페이별 순서를 알려 줍니다 | 음성 안내를 켜면 말풍선이 "휴대폰을 대서 결제하려면"처럼 뜻을 풀어 줍니다 |

**동작 규칙**
- 카드를 못 읽거나 결제가 거절되면 '다시 시도'나 '다른 카드로 결제', 또는 '결제 방법 다시 고르기'를 고릅니다. 다시 시도 횟수에는 제한이 없습니다.
- 현금을 넣다가 '결제 취소'를 누르면 넣은 돈을 모두 돌려준 뒤 결제 방법 화면으로 돌아갑니다.
- 거스름돈·카드를 챙겨야 하는 화면과 출력 중인 화면은 저절로 넘어가지 않습니다.
- 결제 중에 '처음으로'를 누르면 "먼저 결제 상태를 확인해 주세요" 창이 뜹니다. 진행 중인 결제나 챙겨야 할 돈·카드를 두고 떠나지 않게 합니다.
- 카드 읽기 실패·거절 화면은 카드가 꽂혀 있을 수 있습니다. 90초 동안 누르지 않으면 뜨는 경고 창과, '처음으로'를 눌렀을 때 뜨는 확인 창 모두 "꽂혀 있는 카드를 꺼내 주세요."를 먼저 알립니다. [디자이너]
- 결제 기계가 답하지 않을 때 몇 초 뒤 오류 화면으로 넘길지는 **[미정]**입니다. 실제 기기를 연결할 때 정합니다.

<a id="s4-10"></a>
### 4-10. 결제 끝 (영수증 · 주문번호표 · 완료)

**하는 일**: 영수증을 받을지 고르고, 주문번호표를 챙깁니다.

**풀려는 문제** (모두 예전 시안의 문제)
- 영수증을 받지 않으면 종이가 하나도 나오지 않아, 주문번호를 외워야 했습니다.
- 손님이 떠난 뒤에도 주문번호가 화면에 남아 다음 손님에게 보였습니다.
- 가장 중요한 주문번호가 작게 보였습니다.

| 요소 | 설계 | 이유 |
|---|---|---|
| 주문번호표 | 영수증을 받든 안 받든 **늘 출력합니다.** "주문번호표는 영수증을 받지 않아도 나와요." | **번호를 외우지 않아도 되게** 합니다. 실제 매장도 주문번호표가 따로 나옵니다. [디자이너] |
| 완료 화면 순서 | 결제가 완료됐어요 → **주문번호(가장 크게, 140)** → 할 일 → 인사(회색) → 처음으로 | 중요한 정보가 너무 작다는 판단으로 순서와 크기를 바꿨습니다. [디자이너] 기획에서도 주문번호를 화면에서 가장 크게 하기로 했습니다 |
| 할 일 | "출력된 주문번호표를 챙겨 주세요." 개인컵이면 "개인 컵을 카운터에 가져다주세요."를 더하고 번호를 붙입니다 | 그림 대신 할 일을 목록으로 보여 줍니다 |
| 저절로 넘어가기 | 완료 화면은 **20초** 뒤 첫 화면으로 갑니다. 영수증 고르기 화면은 **30초** 뒤 영수증 없이 번호표만 출력합니다. 남은 초를 늘 보여 주고, 화면을 누르면 다시 셉니다 | P6. 번호표가 이미 손에 있으므로 짧게 넘어갑니다. 완료 20초는 기획 결정입니다.[^d13] 30초는 느린 손님도 번호표는 받게 하려는 디자이너 가안입니다 |
| 출력 실패 (영수증·주문번호표) | 두 화면을 같은 모양으로 둡니다. "결제가 완료됐어요"와 주문번호(크게), 무엇이 출력되지 않았는지, **"직원을 부르면 주문번호표를 대신 드려요."** 버튼은 **'번호표 없이 마치기' / '직원 부르기'**. 개인컵이면 개인컵 안내도 넣습니다 | 종이가 없으면 손님에게 남은 기록은 화면의 번호뿐입니다. 그래서 **20초 뒤 말없이 넘어가지 않고**, 주문 화면처럼 90초 뒤 경고 창("첫 화면으로 돌아가면 주문번호가 화면에서 사라져요.")에서 30초를 센 뒤 넘어갑니다. 기기가 한 화면에 묶이지 않게 끝은 둡니다. 직원 버튼을 따로 만들지 않고 버튼 위에 왜 부르는지를 씁니다(P4). 결제는 끝났으므로 다시 결제하는 버튼은 없습니다. [디자이너] |
| 결제 뒤 '처음으로' | 번호표가 아직 나오지 않은 화면(결제 완료·영수증 고르기)에서 '처음으로'를 누르면 **주문번호표를 먼저 출력한 뒤** 완료 화면에서 마칩니다. 출력 실패 화면에서 누르면 "첫 화면으로 돌아가면 주문번호가 화면에서 사라져요." 확인 창('계속 보기' \| '처음으로 돌아가기')을 띄웁니다. 화면 안 '번호표 없이 마치기'는 이름이 할 일을 말하므로 묻지 않습니다 | 예전에는 묻지 않고 바로 첫 화면으로 가서, 번호표도 받지 못한 채 주문번호를 잃을 수 있었습니다(P3, P6). [디자이너] |
| 받는 곳 안내 | 넣지 않았습니다 | 매장마다 다르기 때문입니다 |

- 주문번호는 ※ 시연값입니다(27번부터).

## 5. 보기 설정과 음성 안내

<a id="s5-1"></a>
### 5-1. 기능바

**풀려는 문제**: 관찰한 키오스크는 도움 기능이 있는데도 아무도 찾지 못했습니다. 글자 없는 흰 선 아이콘이 광고 위에 있었고, 화면마다 자리가 달랐습니다.[^f04]

| 설계 | 이유 |
|---|---|
| 모든 화면 맨 아래, 같은 자리 | 한 번 찾은 기능을 다음 화면에서 다시 찾지 않게 합니다(P4) |
| 아이콘마다 글자: 큰 글씨 / 고대비 / 낮은 화면 / 음성 안내 / 직원 부르기 / 처음으로 | P2 |
| 불투명한 바탕 위에 둠 | 뒤가 밝은 광고든 무엇이든 아이콘이 잘 보이게 합니다[^f04] |
| 켜진 기능은 바탕색이 바뀌고 오른쪽 위에 체크 | 지금 켜져 있는지 알 수 있습니다 |
| 일반 화면 3칸 × 2줄, 낮은 화면 6칸 한 줄 | |
| 아이콘은 배리어프리 키오스크 디자인 시스템의 것 | [기준] |

- 직원을 부르면 기능바 위에 "직원 도움을 기다리고 있어요 ›" 줄이 생기고, 버튼 이름이 '직원 호출 중'으로 바뀝니다.

**남은 질문**: 퀴즈에서 '확대보기'와 '가+' 버튼의 차이를 헷갈린 사람이 많았습니다(정답률 65.2%). '큰 글씨'라는 이름이 "글자만 커진다"는 뜻으로 읽히는지는 확인하지 않았습니다([8장 질문 5](#ch8)).

<a id="s5-2"></a>
### 5-2. 큰 글씨

**풀려는 문제**: [설문] 자유 응답에서 "글자가 작다·읽기 어렵다"가 가장 많았습니다(22건 중 8건).

| 글자 | 기본 글씨 | 큰 글씨 |
|---|---|---|
| 화면 제목 | 48 | 50 |
| 메뉴 이름 등 주요 글자 | 36 | 40 |
| 본문 | 32 | 32 (아래 '몇몇 곳'은 36) |
| 정보 값 | 32 | 40 |
| 작은 글씨 · 진행바 | 28 | 32 |

(단위: 1080×1920 화면 기준 px. 실제 mm는 재지 않았습니다.)

- **몇몇 곳만 36**: 장바구니 전체, 확인 화면의 항목 이름, 직원 창·알림 줄, 현금 금액 줄, 메뉴 스크롤 안내, 이용 방법 안내 문구, 기능바 글자. 큰 글씨에서도 본문·작은 글씨·탭 이름이 기본 글씨와 같은 32라 작아 보여서 올렸습니다. 모든 곳을 36으로 올리는 안은 고르지 않았습니다.
- 가장 작은 글자는 28입니다(기본 글씨의 작은 글씨·진행바).
- 서체는 Pretendard, 줄 간격은 140%입니다. 배리어프리 키오스크 디자인 시스템의 27인치 글자 크기 표를 기준으로 했습니다.

<a id="s5-3"></a>
### 5-3. 고대비

| 설계 | 이유 |
|---|---|
| 검정 바탕 #000000, 흰 글자(대비 21:1), 노란 버튼 #F8DA29에 검정 글자 | [기준] NIA(한국지능정보사회진흥원) 키오스크 UI 가이드의 고대비 색을 그대로 씁니다. 고대비에서는 브랜드 색보다 알아보기 쉬운 것이 먼저입니다 |
| 브랜드 빨강을 쓰지 않음 | 고대비에서는 노랑이 버튼 색을 맡습니다 |
| 색만으로 뜻을 전하지 않음 | 아이콘·문구·테두리를 함께 씁니다 |
| 글자와 바탕의 대비 4.5:1 이상 | [기준] WCAG 2.x. 일반·고대비 모두 38쌍을 자동으로 검사합니다 |
| 음성 테두리는 흰색, 말풍선은 진회색 | 노랑을 쓰면 노란 버튼·켜진 기능과 헷갈립니다 |

- 관찰한 키오스크의 고대비는 청록색이었고, 노안일수록 청색이 잘 안 보인다는 지적이 있었습니다.[^f03] 우리 고대비는 이 점을 고려해 버튼·글자에 청색을 쓰지 않습니다.
- **아직 하지 않은 것**: 관찰 기록은 고대비에서 사진을 빼거나 단순하게 하라고 권했습니다. 우리 고대비는 메뉴 사진을 그대로 보여 줍니다([7장](#ch7)).

- 실제 기기에서 버튼이 바닥에서 몇 mm 높이에 오는지는 재지 않았습니다.

<a id="s5-6"></a>
### 5-6. 음성 안내

**하는 일**: 화면을 어느 정도 볼 수 있지만 글을 읽기 어렵거나 시력이 약한 사람에게, 다음에 할 일과 버튼 위치를 소리로 알려 줍니다. 화면을 전혀 볼 수 없는 사람을 위해 화면 전체를 읽어 주는 기능은 아닙니다.

| 설계 | 이유 |
|---|---|
| **다음에 할 일과 위치만 읽음.** 메뉴 이름·가격·고른 내용·금액은 읽지 않음 | [기획][^d04] 금액 같은 정보는 자리만 알리고 그 칸에 테두리를 칩니다. 예: "결제할 금액은 결제 방법 버튼 위에 있어요." |
| **바뀌는 숫자는 읽지 않음** (주문번호·음량) | 주문번호는 큰 글자와 주문번호표가 맡습니다. 번호표가 나오지 않은 화면에서만 "주문번호는 화면에 크게 적혀 있어요."라고 자리를 알립니다. 그래서 모든 문장을 미리 만들어 둘 수 있습니다. [디자이너] 늘 같은 숫자인 개인컵 500원 할인은 읽습니다 |
| 읽는 곳에만 노란 테두리 | 예전에는 화면을 어둡게 덮었는데, 음성이 끝나도 어두운 막이 남고 주문번호까지 가려졌습니다 |
| 같은 문장은 한 주문에서 처음 한 번만 저절로 읽음. 다시 들으려면 '다시 듣기' | 같은 화면에 돌아올 때마다 같은 말을 되풀이하지 않습니다. [디자이너] |
| 경고·오류는 나올 때마다 읽음 | [디자이너] |
| **7초** 동안 아무것도 누르지 않으면 지금 화면 안내를 한 번 더 읽음 | [기획][^d04] 기획에서 정한 6~8초의 가운데 값입니다. 기다리기만 하는 화면에서는 다시 읽지 않습니다 |
| 대화상자가 열리면 대화상자 안내만 읽고, 버튼마다 그 버튼에 테두리를 침 | 예전에는 대화상자가 열리면 음성이 멈췄습니다 |
| 말풍선은 꼭 필요한 곳에만 | 화면 글이 같은 말을 하면 말풍선을 두지 않습니다 |
| 짧고 같은 문장 | 한 줄에 할 일 하나, 버튼 이름은 화면 글자 그대로, "~하려면, ○○를 눌러 주세요."처럼 무엇을 하려는지 먼저 말함('아니면' 대신). 같은 상황은 같은 문장(직원을 부른 뒤, 고르기 질문 등). 돈·카드·결제 여부·경고·오류는 줄이지 않음 | 듣고 바로 알 수 있게 하고, 미리 만들어 둘 문장 수를 줄입니다(175줄 → 164줄, 2026-10-28). [디자이너] |
| 녹음 파일 | 녹음 파일(TTS)이 있으면 그 파일을 틀고, 없는 줄은 브라우저 음성으로 읽습니다 | 기기마다 다른 목소리 대신 같은 목소리(여성, 보통 빠르기)로 들려주되, 파일이 일부만 있어도 안내가 끊기지 않게 합니다(2026-10-29). [디자이너] |
| 버튼 안내 위주 | 버튼마다 한 줄씩 읽고 그 버튼에만 테두리를 두릅니다. '담은 메뉴를 확인해 주세요'처럼 버튼을 가리키지 않는 줄은 뺍니다. 화면당 시간 상한은 두지 않습니다 | 노년층이 어려워하는 것은 무엇이 어디에 있는지 찾는 일입니다. 두 버튼을 한 줄에 묶어 읽으면 짧아지지만 버튼을 하나씩 짚어 주지 못합니다. 짧아진 음성이 실제로 충분한지는 이용자로 확인해야 합니다. [디자이너] |
| 음량 0~10, 처음 5. 빠르기는 보통(1) | 새 주문마다 5로 돌아갑니다(P8). 음량을 바꿔도 "음량 N"을 말하지 않습니다. 바뀐 크기는 읽던 문장을 다시 읽어 들려주고, 쉬는 중이면 '다시 듣기'로 들을 수 있습니다 |

**한계**
- 브라우저에 들어 있는 한국어 음성으로 읽기 때문에 기기마다 목소리가 다릅니다.
- 노란 테두리 #FFC400는 흰 바탕과의 대비가 1.6:1로, 그림·테두리 기준(3:1)에 못 미칩니다. 노랑과 검정 선을 겹쳐 쓰자는 의견이 있었지만 지금은 노랑 한 겹입니다. 실제 이용자로 확인해야 합니다.
- 7초가 짧은지 긴지는 매장 소음 속에서 확인하지 않았습니다.
- 읽는 문장 전체는 [음성 안내(TTS) 문장과 설정](VOICE-TTS.md)에 있습니다.

## 6. 문제가 생겼을 때

| # | 상황 | 화면에서 일어나는 일 |
|---|---|---|
| 1 | **90초 동안 아무것도 누르지 않았다** | "아직 주문 중이시죠?" 창에 "30초 후 첫 화면으로 돌아가요."가 나옵니다. '계속 주문하기'를 누르면 다시 90초를 셉니다. 30초가 지나면 주문이 지워지고 대기 화면으로 갑니다 |
| 2 | **직원을 불렀다** | "직원을 불러드릴까요? / 직원을 기다리는 동안 고른 메뉴는 그대로 보관돼요." 호출 위치는 '키오스크 2번'(※ 시연값). 부른 뒤에는 "직원 도움을 기다리고 있어요 / 이 자리에서 잠시 기다려 주세요." 이 동안 시간 초과를 세지 않습니다 |
| 3 | **90초가 지나도 직원이 오지 않았다** | "아직 직원이 오지 않았어요 / 다시 부르거나 카운터에 말씀해 주세요." 화면이 카운터로 가라고 했으니 손님이 자리를 뜰 수 있어서, 이때부터 시간 초과를 다시 셉니다. 90초는 ※ 시연값입니다 |
| 4 | **직원 호출을 취소하고 싶다** | '호출 취소' → "직원 호출을 취소할까요? / 고른 메뉴와 장바구니는 그대로 유지돼요." |
| 5 | **담아 둔 메뉴가 품절됐다** | 장바구니 맨 위 "주문할 수 없는 메뉴" 칸에 모입니다. 뺄 때까지 결제할 수 없습니다 |
| 6 | **메뉴를 불러오지 못한다** | 10초 뒤 "메뉴를 불러오지 못했어요"와 '다시 불러오기'. 계속 안 되면 직원을 부르라고 안내합니다 |
| 7 | **카드를 읽지 못했다 / 거절됐다** | "카드를 읽지 못했어요" → '다시 시도'. "카드 결제가 거절됐어요 / 결제되지 않았어요." → '다른 카드로 결제'. 둘 다 '결제 방법 다시 고르기'도 할 수 있습니다 |
| 8 | **결제됐는지 모른다** | "결제 여부를 확인하지 못했어요 / 다시 결제하지 말고 직원에게 확인을 요청해 주세요." 직원 부르기만 할 수 있고 '처음으로'도 잠깁니다 |
| 9 | **결제 기기가 고장 났다** | "기기 문제로 이 결제방법을 쓸 수 없어요 / 결제되지 않았어요." 다른 방법이 남아 있으면 그 방법을 고르고, 없으면 직원을 부릅니다 |
| 10 | **현금 장치가 꺼져 있다** | 결제 방법 화면에서 현금 칸이 회색으로 잠기고 "지금 쓸 수 없어요"가 나옵니다 |
| 11 | **지폐가 돌아 나왔다** | "지폐를 읽지 못했어요 / 나온 지폐를 펴서 다시 넣거나 다른 지폐를 넣어 주세요." |
| 12 | **거스름돈이나 돌려받을 돈이 다 나오지 않았다** | "현금 결제를 마무리하지 못했어요 / 돈을 더 넣지 말고 직원을 불러 주세요." 받을 돈·나온 돈·아직 못 받은 돈을 보여 줍니다 |
| 13 | **영수증·주문번호표가 나오지 않았다** | "결제가 완료됐어요"와 주문번호, "직원을 부르면 주문번호표를 대신 드려요." '번호표 없이 마치기' 또는 '직원 부르기'. 저절로 넘어가지 않고, 90초 뒤 경고 창("주문번호가 화면에서 사라져요")에서 30초를 센 뒤 첫 화면으로 갑니다 |
| 14 | **결제 중에 '처음으로'를 눌렀다** | 돈·카드가 기계에 걸려 있으면 "먼저 결제 상태를 확인해 주세요". 카드 읽기 실패·거절 화면이면 "꽂혀 있는 카드를 꺼내 주세요."를 먼저 쓴 확인 창. 결제가 끝났는데 번호표가 아직 없으면 번호표부터 출력하고, 출력 실패 화면이면 "주문번호가 화면에서 사라져요" 확인 창. 그 밖에는 "진행 중인 주문이 있어요. 처음 화면으로 돌아가시겠어요? / 지금 고른 메뉴와 장바구니가 모두 사라져요." |
| 15 | **음성이 나오지 않는다** | "음성 안내를 재생하지 못했어요 / 화면의 글 안내를 따라 이용해 주세요." |
