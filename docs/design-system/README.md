# 현재 시안의 디자인 시스템과 Figma 인계 기준

기준일: 2026-10-12. 기존 디자인과 동작을 보존하는 구조 정리다. Figma 파일 생성·변수 바인딩·프로토타입 연결은 아직 실행하지 않았다.

## 원본과 생성 파일

| 역할 | 원본 | 사용처 |
|---|---|---|
| 색상 팔레트 | `src/color-tokens.json` | 기존 Gray / Light / HC |
| 의미 색상 | `src/colorSystem.ts` | 같은 CSS 변수 이름을 기본/고대비에서 전환 |
| 여백·반경·글자·컴포넌트 규격 | `src/design-system/tokens.json` | TS 컴포넌트와 생성 CSS의 공통 원본 |
| 글자 역할 해석 | `src/design-system/typography.ts` | `useType()`에서 모드에 맞춰 선택 |
| 수치 토큰 접근 | `src/design-system/metrics.ts` | 레이아웃·버튼·옵션·음성·결제 등의 역할별 export |
| CSS 변수 | `src/design-system/tokens.css` | 자동 생성. 직접 편집하지 않음 |
| 컴포넌트/모드 목록 | `src/design-system/catalog.json` | Figma 이름·코드 경로·주요 속성 38개 항목 |
| Figma 인계 데이터 | `docs/design-system/figma-handoff.json` | 위 목록 + 실제 결제/음성/직원 상태 소스에서 생성 |

`npm run tokens:generate`로 CSS를 갱신하고, `npm run design:export`로 인계 데이터를 갱신한다. `npm run check`는 두 생성 파일이 원본과 일치하는지 확인한다. 인계 JSON은 Figma에 자동으로 컴포넌트를 만드는 플러그인 파일이 아니다.

## 이번에 공통화한 부분

- 기본·채택된 큰 글씨·legacy 글자 크기/굵기/줄높이를 원본 하나로 모았다. 기존 `useType` 반환값을 유지한다.
- 1080×1920 캔버스, 640px 낮은 배치 상단, 버튼 규격, 원형 체크 간격 12px, 모달, 스크롤 그림자, 음성 dim/컨트롤 규격을 역할별 토큰으로 옮겼다.
- 낮은 메뉴·상품·옵션·확인·장바구니·결제방법·결제 안내의 상단을 `LowScreenHeader`로 통합했다.
- 낮은 화면 5종의 하단 기능 정의를 `useLowScreenUtilities`로 통합했다. 각 화면의 복귀/안내 동작은 유지한다.
- `ItemOrderButtons`로 메뉴 복귀/담기 동작을 공유한다. 수량 영역과 스크롤 경계는 호출 화면에 남긴다.
- `MenuCard`, `LowMenuCard`, `PaymentMethodChoice`를 독립 컴포넌트로 분리했다.
- 카드·현금·모바일이 공유하는 `PaymentAmount`, `PaymentMoneySummary`를 분리했다.
- 기존 Button, SelectionCard, FilterChip, QuantityStepper, ProgressStep, DialogFrame, VoiceOverlay 등은 재사용하고 수치의 원본을 정리했다.

기존 음성 강조의 `data-voice-*` 표시, 원래 스크롤 영역, 포커스/모달 처리, 상태 reducer는 유지했다. SVG 그림 자체의 좌표, 결제/상품 데이터, 한 화면에서만 쓰는 배치 보정값은 억지로 공통 토큰에 합치지 않았다. 모든 JSX를 개별 컴포넌트로 분리하는 방식은 사용하지 않았다.

## 같은 값이어도 다른 역할

하단 보조 기능 반경과 결제 금액 반경은 모두 12px이지만 `radius.utility`와 `radius.amount`로 구분한다. 이후 한 역할을 바꿀 때 다른 영역이 함께 변하지 않게 한다.

다음 차이는 기존 시안에 실제 존재하므로 보존했다. 통일하려면 별도 디자인 판단이 필요하다.

| 항목 | 보존한 차이 |
|---|---|
| 주문 버튼 | 기본 높이 128px / 낮은 담기 104px / 낮은 옵션 다음 버튼 128px |
| 낮은 확인의 복귀 버튼 | Tertiary + 큰 글씨. 일반 주문 바는 Utility + 작은 버튼 글자 |
| 낮은 확인의 담기 문구 | `금액 · 담기`. 일반 주문 바는 `금액 담기` |
| 결제방법 선택 화면 | 결과 화면과 다른 버튼/선택 카드 반경이 남아 있음. 구조 정리에서 재디자인하지 않음 |
| 상품 카드 | 기본 세로 사진 카드 / 낮은 가로 사진 카드. 이미지 맞춤 방식도 각각 유지 |
| 낮은 상단 설명 | 일반 화면은 보조 글자색. 결제 진행 화면은 기존 기본 글자색 |
| 스크롤 안내 | 상품·옵션의 96px 옅은 그림자와 메뉴·장바구니의 문구 포함 안내는 별도 패턴 |

`previews/LowScreen*.tsx` 중 일부는 현재 앱에서도 사용한다. 이름만 보고 미사용 시안으로 제외하지 않는다. 이전 카드 결제 단독 화면과 카드/언어/유틸리티 비교안은 최신 본 흐름과 분리해 참고 목록으로 남겼다.

## Figma 구성

사용자에게 보여줄 페이지는 **기본모드 / 낮은 화면 / 고대비모드 / 음성안내 / 직원부르기 안내**로 나눈다. 내부 속성은 독립적으로 구성한다.

| 축 | 상태 |
|---|---|
| 배치 | 기본 / 낮은 화면 |
| 색상 | 기본 / 고대비 |
| 글자 | 일반 / 큰 글씨 |
| 음성 | 꺼짐 / 안내 / 숨김 / 재생 경고 |
| 직원 | 닫힘 / 호출 확인 / 대기 / 취소 확인 |

낮은 화면+고대비+음성을 함께 표현할 수 있어야 한다. 모든 축을 곱한 거대 컴포넌트 세트 대신, 배치 컴포넌트·색상 모드·중첩 인스턴스·안내 상태를 조합한다. Figma 변수 이름은 토큰 경로, 코드 표기는 실제 `var(--...)` 이름을 따른다. 아이콘/이미지는 기존 자산을 쓰고 교체 가능한 인스턴스로 구성한다.

화면들은 공통 컴포넌트의 인스턴스로 구성하고, 안내 문구·금액·주문번호는 텍스트 속성으로 둔다. 주문번호는 `[주문번호]` 자리표시를 유지한다.

## 흐름 연결 기준

핵심 경로는 이용 방법 → 메뉴 → 상품 → 옵션 또는 기본값 확인 → 장바구니 → 결제방법 → 카드/현금/모바일 → 영수증 → 완료다. 상품 종류와 온도에 따라 옵션 단계가 달라진다. `App.tsx`, `orderEntry.ts`, `selectionSummary.ts`가 실제 분기의 기준이다.

- 사용자가 누르는 버튼과 카드 감지/승인/지폐 계수/출력 등 **시연 이벤트**를 구분한다. 자동 승인이나 실제 직원 호출로 표현하지 않는다.
- 카드 읽기 실패·승인 거절·기기 오류·결제 결과 미확인을 별도 상태로 유지한다.
- 현금은 정상적으로 돌아온 지폐 안내와 돈 회수/반환 문제가 있는 상태를 구분한다. 투입액에 따른 다음 상태는 `paymentSessionReducer`를 따른다.
- 모바일 도움말은 코드 스캔 위의 모달이다. 앱 선택이 결제수단 선택처럼 이어지지 않게 한다.
- 영수증 출력 실패는 성공한 결제 상태를 유지한다. 재결제로 연결하지 않는다.
- 직원 안내를 닫아도 호출 대기는 유지하고, 명시적으로 취소해야 해제한다. 이전 주문 상태로 복귀한다.
- 음성안내는 문장, 대상 영역, 강조 그룹, 재생/닫기, 실패 경고를 기록한다. 실제 TTS 타이밍·스크롤 clipping·키보드 포커스는 웹에서 검증한다.

인계 데이터의 32개 결제 scene에는 모바일 도움말 모달 4개가 포함된다. 현금 오류/거부 사유와 투입 유무를 펼치면 40개 사례다. 이는 모든 상품·금액·모드의 조합 수가 아니다.

## 검증

`verification.json`에 대표 17개 상태의 브라우저 실측 결과를 기록했다. 1,814개 표시 요소의 위치·크기·주요 스타일에서 변경 0건이다. 기본/낮은/고대비/작은 글씨/음성 실패/직원 모달을 포함한다. 최초 12개는 변경 전 커밋 기준, 추가 5개는 메뉴·결제 카드 분리 전 기준이다.

실제 브라우저에서 낮은 메뉴 → 아메리카노 상품 → 기본 주문 → 따뜻하게 → 확인 → 담기 → 장바구니 → 카드 안내를 클릭하고 4,700원 유지, 직원 확인 → 대기 → 닫기 후 호출 상태/주문 화면 유지를 확인했다.

자동 검사는 기존 색상 대비, 주문 진입/옵션 변경/수량/장바구니, 카드·현금·모바일/영수증, 직원 대기/취소, 음성 선택/중단/실패/배치 검사를 사용한다. 대표 화면 검증은 모든 상품과 음성 재생 시점 조합을 보증하지 않는다.

Figma 이관 시에는 대상 파일 확정 → 기존 라이브러리 확인 → 변수/스타일 → 컴포넌트 → 화면 인스턴스 → 프로토타입 연결 → 원본과 비교 순서로 진행한다. 캡처만 붙인 파일을 이관 완료로 처리하지 않는다.
