# 노년층 친화 카페 키오스크 — UX/UI 설계와 퍼블리싱

노년층 사용자가 주문 과정에서 필요한 정보와 다음 행동을 쉽게 찾을 수 있도록, UX 흐름과 UI 정보 위계를 설계·구현하는 프로젝트입니다.

화면 디자인과 동작을 직접 눌러보고 검토하기 위한 **시연용 구현**입니다. 예시 데이터로 동작하며, 실제 주문·결제 서비스가 아닙니다. 서버가 없는 UI 전용이라 새로고침하면 상태가 초기화됩니다.

- 시연(기본 퍼블리싱본): https://senior-cafe-kiosk-design.vercel.app/ — 설치·로그인 없이 열립니다. 아래 "현재 개발 현황"의 Toss·개인컵 변경은 이 배포본에 아직 반영되지 않았을 수 있습니다.
- 저장소: 원본 [newroum/senior-cafe-kiosk-design](https://github.com/newroum/senior-cafe-kiosk-design) · 코드포코리아 작업본 [Code-for-Korea/senior-cafe-kiosk-design](https://github.com/Code-for-Korea/senior-cafe-kiosk-design). 기본 브랜치는 `main`입니다.

## 현재 개발 현황

| 기능 | 상태 |
|---|---|
| 주문 흐름(이용방법→메뉴→옵션→장바구니→결제→완료) | ✅ 구현 |
| 보기 설정: 큰 글씨 · 고대비 · 낮은 화면 | ✅ 구현 |
| 음성 안내(TTS) | ✅ **녹음 파일 전용**(브라우저 합성음 미사용). 녹음이 없는 문장은 무음 — 녹음 보강 필요 |
| **카드 결제** | ✅ **Toss 테스트 결제창 연결**(클라이언트 전용 데모). 성공/취소·이탈/실패를 토스 결과로 판정 |
| 현금 · 모바일 결제 | 🟡 시뮬레이터(실제 기기 없음). 공개 화면에서는 단계가 자동 진행, `?preview=dev`에서 `시연:` 버튼으로 수동 |
| **개인컵 할인(포장)** | ✅ 포장 결제 진입 시 "개인컵 있나요?" → 모달에서 음료 선택 → 한 잔당 500원 할인 |
| 다국어(화면 번역) | 🚧 **준비 중** — 언어 버튼을 누르면 "준비 중입니다" 안내만 뜨고, 지금은 한국어로만 동작 |
| 주문 전송·저장, 결제 승인(서버), 프린터, 직원 호출 | ⛔ 미연결(의도된 시연 범위). 아래 "시연의 한계" 참고 |

### 결제(Toss 테스트) 참고

- **카드만** Toss 테스트 결제창으로 연결돼 있습니다. **클라이언트 전용**이라 승인(confirm) API는 호출하지 않습니다 — 결제창 인증 후 성공 리다이렉트를 "완료"로 보여 주는 데모입니다(실제 승인·청구 없음). 진짜 승인까지는 서버(또는 서버리스) confirm 연동이 다음 단계입니다.
- 실행하려면 `.env`에 **API 개별 연동 키의 클라이언트 키**(`test_ck_…`)를 넣습니다. 주문서형 키(`test_gck_…`)는 동작하지 않습니다.
  ```
  VITE_TOSS_CLIENT_KEY=test_ck_...
  ```
- 키가 없으면 카드도 기존 시뮬레이터로 동작합니다(순수 UI 데모). `?toss=off`로 강제할 수도 있습니다.

## 설계 구간(주문 흐름)

대기 화면 → 이용방법 선택(**매장이용 · 포장**) → 메뉴 → 상품 정보 → 고르기(온도·크기·카페인·얼음) → 고른 내용·수량 확인 → 장바구니 → (포장이면 개인컵 선택) → 결제(카드·현금·휴대폰) → 완료(주문번호표·영수증).

품절, 메뉴 불러오기 실패, 결제 오류, 직원 부르기 같은 문제·상태 화면도 함께 설계했습니다. Figma ‘10 · 주문’, ‘11 · 결제’, ‘12 · 문제·상태’, ‘13 · 음성 안내’, ‘14~16’(기본 글씨·낮은 화면·고대비 견본) 페이지에 나눠 두었습니다.

- Figma: https://www.figma.com/file/CoEH6OGEUuTMQ2HRGR3B03?type=design

## 실행과 확인

React · TypeScript · Vite 기반입니다. Node 22를 씁니다(개발 도구 설정은 `.mise.toml`, 의존성 버전은 `pnpm-lock.yaml` 참고).

```sh
pnpm install
pnpm dev            # 로컬 미리보기 (카드 Toss 결제는 .env의 VITE_TOSS_CLIENT_KEY 필요)
pnpm run check      # 타입·색상·주문·장바구니·결제·음성 안내 검사
pnpm build
```

시연 상태를 지정하는 주소 예시:

- `/?screen=cart&cart=1,2,3&large=1` — 큰 글씨 장바구니에 예시 상품 3개
- `/?screen=review&product=1&temp=HOT&size=M&caffeine=CAFFEINATED` — 처음 담기 전 선택 확인
- `?preview=dev` — 결제 `시연:` 버튼과 품절·현금 장치·메뉴 불러오기 같은 상태 전환 막대 표시
- `?toss=off` — 카드도 기존 시뮬레이터로(Toss 결제창 없이)

보기 설정: `?large=1`(큰 글씨) · `?low=1`(낮은 화면) · `?hc=1`(고대비). 전체 목록은 `src/devParams.ts`.

일반 미리보기는 1080×1920 화면을 브라우저 크기에 맞춰 축소합니다. 이 화면만으로 실제 기기의 문자 높이·가독성을 검증한 것으로 보지 않습니다.

## 배포

`main`에 합쳐지면 Vercel이 검사(`pnpm run check`)와 빌드를 거쳐 시연 주소에 자동 게시합니다. 검사가 실패하면 이전 게시본이 남습니다. 빌드 설정은 `vercel.json`에 있습니다. Toss 카드 결제를 배포본에서 쓰려면 Vercel 프로젝트 환경변수에도 `VITE_TOSS_CLIENT_KEY`를 등록해야 합니다(빌드 시 번들에 들어가므로 재배포 필요).

작업은 `main`에서 갈라진 짧은 브랜치(예: `fix/…`, `docs/…`, `feat/…`)에서 하고 pull request로 합칩니다. 작업 브랜치를 push하면 Vercel이 그 브랜치 미리보기를 따로 배포합니다.
